# 表示言語とAI依頼文の保守

## 対応する9ロケール

日本語 `ja`、英語 `en`、簡体字中国語 `zh`、繁体字中国語 `zh-TW`、スペイン語 `es`、ドイツ語 `de`、フランス語 `fr`、韓国語 `ko`、ポルトガル語 `pt`。既存ブラウザ保存の `zh` は変更せず、HTMLには `zh-CN` を設定する。繁体字のHTMLは `zh-TW`。ポルトガル語はブラジルを意識しつつポルトガルでも読める表現を使う。

`src/i18n/locales.ts` が選択肢・HTML言語・AIの回答言語の定義。保存キーは従来の `mpw-language` のまま。初期値は日本語。未知の保存値を言語として採用しない。切替は表示と依頼文のみを更新し、USB/BLE接続・実行・編集内容・未適用設定を変更しない。

## 画面の翻訳を追加する

既存の `*Messages.ts` には日本語キーと `en` / `zh` を登録する。追加6言語は `src/i18n/locales/*.json` の同じ日本語キーへ自然な翻訳を登録する。キー・JSON項目名・GPIO・UUID・製品名・プロトコルIDや `{count}` などの差し込み変数は翻訳しない。利用者の作品名やコード、機器のラベルやログは原文のまま扱う。

- `node scripts/locale-source.mjs`：固定UI文言の一覧を抽出する。利用者データは含めない。
- `npm run check:locales`：6辞書の全件対応、余分なキー、空欄、差し込み変数の一致を確認する。ビルドでも必須実行。
- `npm test`：既存3言語に加えて、9言語のカタログ網羅、言語切替・HTML lang、依頼文の言語指定とコード原文の保持を確認する。

翻訳作業中だけ使う短いID辞書は `node scripts/check-locales.mjs --materialize` で通常の日本語キーへ機械変換できる。全件・差し込み変数が一致しない辞書は変換できない。チェック済み辞書を変更するときも `apply_patch` を使う。

## AIへ渡す依頼文

日本語・英語・簡体字中国語は従来の長文仕様を維持する。追加6言語には、その言語の案内と回答言語の明示指定を入れ、共通技術仕様は英語版を同梱する。仕様書の英語と、AIが利用者へ回答する言語は別。質問・選択肢・要約・説明・新規コメントを選択言語にするよう指定する。固定仕様と元の作品の明示指定を保持し、Arduino/C++へ切り替えない。AIの応答自体をアプリが強制できるわけではない。

修正依頼では、実行時のコード・ログ・機器情報・設定スナップショットを原文で保持する。追加6言語へ切替えても日本語の既定テンプレートに戻さず、英語で返答せよという矛盾する指定を入れない。登録済み基準コードを翻訳・再生成したり、未確認の実機動作を確認済みとして扱ったりしない。

## Androidなどで全文をAIへ渡す

準備文・エラー修正・MicroPythonへの書き直し依頼には、コピーの隣にファイル保存ボタンを表示する。保存はUTF-8の `.txt`。全文を省略せず、クリップボードのAPIを使わない。利用者がダウンロードからファイルを選び、AIの会話へ自分で添付・送信する。AIに添付機能がない場合はファイルを開いて全文をコピーする。

秘密情報らしい代入が見つかった場合は確認を求め、拒否したらファイルを生成しない。この検出は補助であり、全秘密情報の検出を保証しない。通知は「ダウンロード開始」とし、端末への保存完了やAIへの送信成功を意味しない。失敗時は手動コピーを案内する。コード・ログの外部自動送信、機器への自動書き込み・実行・起動設定変更は行わない。

自動テスト・ビルドはAndroid実機のダウンロードや各AIサービスの添付可否を保証しない。公開前に端末・ブラウザでファイル末尾、UTF-8表示、AIへ添付した内容、長い翻訳でのレイアウトを確認する。

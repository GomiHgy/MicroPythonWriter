# LED・ボタンのシミュレーション

「プログラム」画面は、左がコード、右がシミュレーション。その下に実機の見守りログを折りたたんで配置する。狭い画面はコード → シミュレーション → ログの順になる。実機のエラー案内はログを閉じても見える。

## 使い方

1. エディタへPythonを入力する。既存の「実行」は実機用。画面だけで試すときは **「シミュレーションを再生」** を押す。
2. 機種・GPIO・LED数をコードと合わせる。「AIの準備」または読み込んだ保存プログラムの設定を初期値にする。設定がなければNanoC6 / GPIO2 / 10個で、シミュレーションの設定欄から変更できる。コードそのものや実機の設定は変更しない。
3. 「本体ボタン」をマウス・タッチで押して離す。短押し・2回押し・長押しの意味はコード次第。キーボードのSpace / Enterでも押下・解放を試せる。NanoC6はGPIO9、AtomS3LiteはGPIO41のactive LOW入力。
4. コードがNanoLED対応のBLEサービスを開始すると仮想リモコンが現れる。LED再生（PLAY）、停止（PAUSE）、消灯（OFF）、明るさ（BRIGHTNESS）、機器役のコードから通知された名前付きモード・演出を試す。必要ならACTION IDも入力できる。通知のLED値ではなく、コードのLED出力を描画する。
5. 出力されたLED数と表示設定が違うときは「コードのLED数を反映」で一致させられる。再生中の演出は止めず、表示数だけを変更し、変更結果を通知する。コード・AI設定・実機設定は変更しない。コードや機器設定を編集した直後は、最新コードを再生してから反映する。
6. テープ / リングは並べ方だけを切り替える。番号1が先頭。最大300個で、RGB値へ再度最大輝度制限を掛けることはしない。

シミュレーターの一時停止は仮想時間も止める。**BLEの「LEDを停止」はコードへPAUSEを渡すだけで、シミュレーターは動き続ける。** リセットはWorkerを破棄し、時間・ボタン・仮想BLE・LEDを初期状態へ戻す。再生を押すまで再実行しない。編集・設定変更後は「最新コードで再生」で最初から始める。アプリの別タブへの移動やブラウザが非表示になった際は一時停止し、押しっぱなしを解除する。

## 対応範囲と限界

- Pyodide 0.29.3（CPython 3.13.2）と本アプリの互換層を使用する。MicroPython VM、ESP32、UIFlow2ファームウェアのエミュレーターではない。CPythonで動くコードが実機で動く保証も、その逆の保証もない。
- `machine.Pin`、RGBの`neopixel.NeoPixel`、WS2812のGRB `machine.bitstream`、`time.sleep/ticks_*`、`M5.BtnA`の基本操作、NanoLEDのBLE GATT入出力を近似する。Pythonの数値計算・関数・クラスを実際に実行し、別のサンプル演出へ置換しない。
- BLEはUUIDがNanoLED仕様に合うサービスを登録し、connectable広告を開始したときだけ仮想接続する。実際のBluetoothアダプターは不要。GATTの実送信・電波・接続品質・競合・実機メモリを保証しない。任意の独自サービスには対応しない。
- 配線・電源容量・LED型番ごとの発色・フリッカー・波形・GPIO電気特性・正確な処理速度は再現しない。GPIOの選択が違えば光は表示されない。フレーム長と表示設定数の不一致は注意表示する。
- ファイル・ネットワーク・センサー・PWM・Timer・複数スレッド等の未対応APIは例外として表示する。`gc.mem_free`など実機のメモリ情報は捏造しない。`micropython.native/viper`は通常のPython関数としてのみ扱い、ネイティブコードは生成しない。
- 対応するChrome/EdgeとWebAssembly JSPIが必要。機能を検出し、未対応なら再生不可と案内する。Safari/iPhoneで動作するという保証はない。初回に約12MBの実行ファイルを同じサイトから取得し、再生を押す前には読み込まない。

## データ・安全性

シミュレーションからWeb Serial / Web Bluetoothを呼ばず、実機へ書き込まない。コードをサーバーへ送って実行する仕組みではない。ランタイムはnpm固定版からビルドに同梱し、CDNや追加Pythonパッケージの自動ダウンロードは行わない。

WorkerでUIと分離し、約20msごとの協調処理、応答監視、Workerの破棄で終了する。ログは8KB、描画は最大300個、BLE入力待ちは16件に制限する。起動は60秒、実行中の応答断は10秒を上限に中止する。

実行前にWorker内の通信・永続ストレージAPIを制限するが、**悪意のあるPythonへの完全なセキュリティ境界ではない**。Pythonの内部参照やエンジン由来の制約は残る。内容が分からないコードは実行しない。元のコードのブラウザ自動保存は従来どおりで、シミュレーションのリセットは保存データを消さない。

## 保守と検証

- `src/services/simulation/`: Worker管理、仮想時計、Pythonハードウェア互換層。`SimulationPanel`は実機のプログラマ/コントローラーとは独立。
- `build/simulationRuntime.ts`: 同一オリジンの実行基盤配信・ビルド出力・改変検出。`simulation-runtime/provenance.json`に配布ファイルのSHA-256を出力する。
- `licenses/simulation/`: Pyodideと内包ライブラリの原文・固定出所。元の実行ファイルは改変せず、MPL対象のソース入手先を第三者ライセンス全文に同梱する。
- `npm test`はUI、Workerの世代管理、仮想時間、Python互換API、実Pyodide + JSPIでの現行入門コード/BLE/LED/busy loopを検証する。実機検証の代わりにはならない。
- `npm run build`は型・同梱ファイル・ライセンスを検査する。依存更新時はCPython/JSPI互換性・内包ライセンスを再確認する。

実行方式の根拠: [PyodideのJSPI/run_sync](https://blog.pyodide.org/posts/jspi/)、[公式0.29.3ソース](https://github.com/pyodide/pyodide/tree/0.29.3)。

# AndroidからM5NanoC6をUSBで操作する

Androidスマホから `main.py` を読み込み・書き込み・実行し、対応UIFlow2ファームウェアの自動実行ON／OFFを変更するための案内。

**接続経路は実装済みだが、AndroidスマホとM5NanoC6を使った実機確認は未実施。** 機種・Android / Chrome / UIFlow2版、USB構成や給電条件によって使えない場合がある。自動テストの成功を実機動作保証とは扱わない。

## 最初に確認すること

- USBホスト（OTG）対応のAndroidスマホ。機種によっては設定画面でOTGを有効にする必要がある。
- Android版ChromeでHTTPSの公開ページを開く。アプリ内ブラウザではなくChromeで開く。PCの開発サーバーを `http://192.168...` 等のLANアドレスで開くだけでは、安全なコンテキストの条件を満たさない。
- データ通信対応USBケーブル。充電専用ケーブルでは接続できない。端子に合わせてOTGアダプタや対応ハブを使用する。
- M5NanoC6へUIFlow2 / MicroPythonが導入済みで、通常モードで起動していること。本体ボタンを押しながら接続してダウンロードモードへ入らない。
- 他のUSBシリアルアプリ、M5Burner、UIFlowのUSB接続を閉じる。このアプリの複数タブ／インストール版から同時接続しない。

スマホからの給電には余裕がない場合がある。最初は本体だけで接続し、LEDを使うときは配線・安全な明るさの上限・電流を確認する。電源不足による再起動を接続不具合と混同しない。別電源を足す場合は、電源を切ってから適切な配線・給電方法を確認し、スマホ側へ逆給電するような接続をしない。

## プログラムを送って試す

1. 必要なコードをファイルにも保存する。ブラウザ内保存は機器内の最新版のバックアップとは限らない。
2. 本体のボタンを押さず、スマホとM5NanoC6をUSBで接続する。スマホ側でUSBの確認が出た場合は、Chromeでのアクセスを許可する。
3. 「プログラム」画面で「USBをつなぐ」を押し、Chromeの選択画面で対象機器を選んで許可する。別のUSBアプリへ自動で開く場合は、そのアプリの占有や既定動作を解除してから試す。
4. 「準備OK」を待つ。接続しただけでは自動実行の設定を変更しない。すでに動いている作品があれば、アプリは停止してMicroPython REPLを取得することを試みる。
5. プログラムを貼り付けて「実行」を押す。機器へ保存してから実行する。「書き込み成功」と「実行開始」の表示を分けて確認し、実際のLEDとボタンの動作を確認する。
6. 書き込み・設定変更中は画面を開いたままにし、スマホをロックしたりアプリを切り替えたりしない。USBケーブルと給電を維持する。

保存済みの機器コードを読む場合は「その他の操作」→「保存済みのプログラムを読む」を使う。編集中コードを置き換える確認に注意する。

ファイル転送の安全条件はPCと同じ。既存の `main.py` を先に消さず、一時ファイルのサイズ・SHA-256・構文確認後に保存を切り替える。転送中に接続が切れた場合は成功表示にせず、復旧後に機器内のコードを読み直して確認する。

## 電源投入時の動きを変える

**完成した作品を自動で動かす:** 先に「実行」で現在のコードを送り、実機の動作を確認する。その後「電源を入れたら自動実行」を押し、確認画面で続ける。

**自動では動かさない設定に戻す:** USB接続して「電源を入れた時の動き」→「自動実行しない設定に戻す」を押し、確認画面で続ける。作品のコードは消さない。

設定変更は対応するUIFlow2の `boot_option` または確認済みNVS操作でのみ行う。対応を検出できなければ設定を変えず案内する。設定の保存後は再起動を指示してUSB接続を閉じる。再接続してON／OFF表示を確認し、電源を入れ直したときの実動作も確認する。機器が再列挙された場合は「USBを選び直す」を使う。

「停止」は今のプログラムを止める操作で、次の電源投入時の自動実行設定は変更しない。

## 接続できないとき

- **選択画面が出ない:** HTTPS、Android版Chrome、OTG設定、データケーブルを確認する。ブラウザのUSB権限を見直し、機器を選び直す。
- **機器が候補にない／開けない:** 他のUSBアプリを閉じ、給電・ケーブル・通常起動を確認する。OSドライバやブラウザの制約でWebUSBから対象インターフェースを利用できない場合は、このアプリだけでは解消できない。PC版Chrome / EdgeのWeb Serial経路を試す。
- **接続したが準備できない:** UIFlow2 / MicroPythonが動いているか確認する。REPLを無効にしたコード、停止要求を無視するコード、フリーズ、スリープ、再起動ループでは設定変更できない場合がある。書き込み失敗の表示後に電源を外し、本体だけで試す。スリープに入る作品ではUSBが途切れることもある。
- **再起動や抜線後に戻れない:** 数秒待ち、「もう一度つなぐ」を試す。前の機器を安全に特定できない場合は「USBを選び直す」。再接続だけで失敗した操作を勝手に再開しない。
- **まだ直らない:** 機種・各版・操作順と、機密情報を除いた見守りログを保存し、アプリ内の復旧ガイドを確認する。必要ならPCとM5Burnerを使った公式の復旧方法へ進む。

**ROMダウンロードモードではこのアプリのコード読み込み・書き込み・起動設定変更はできない。** このモードではMicroPython REPLが動いていない。UIFlow2自体の導入・消去・復旧フラッシュ機能は含めていない。ダウンロードモードに入るだけでは自動実行はOFFにならず、ファームウェアの再書き込みではコードや設定を失う可能性がある。通常モードへ戻るだけなら、書き込みを行わずボタンを押さずに電源を入れ直す。

## 接続方式と対応範囲

アプリは `navigator.serial` が使える場合にWeb Serialを優先し、それがない場合だけ `navigator.usb` を使ったWebUSB CDC fallbackを選ぶ。Web Serialでの許可キャンセルや接続失敗を理由に、別のUSB選択画面を勝手に開かない。

WebUSB側はEspressif VID `0x303a` のnative CDC-ACMに限定し、ACM制御インターフェースとCDCデータインターフェースがそれぞれ1つ、bulk IN / OUTが各1つの構成を検査する。複数の通信候補を推測で選ばない。PIDは固定しないが、VIDだけで機種やMicroPython動作を確認済みにはしない。USB-UART変換器のCP210x / CH340 / FTDI、任意のvendor-specificインターフェースは対応外。AtomS3Liteも実際のファームウェアのCDC構成が条件に合う場合に限られ、NanoC6での確認を流用しない。

通常通信だけを行い、USB制御信号でダウンロードモードへ入れる操作は行わない。hardware USB Serial/JTAGの `303a:1001` ではDTR／RTSをともにfalseにして、起動設定変更後の再起動を妨げない。それ以外の対応CDCではRTSをfalseに保ち、DTRのみtrueにする。C6のDTRとdownload-mode flagの関係は[ESP32-C6 TRMのUSB Serial/JTAG Controller、表32.3-2](https://documentation.espressif.com/esp32-c6_technical_reference_manual_en.pdf)を参照。この処理も実機での再起動確認とは別。

シミュレーターの専用WorkerではWebUSBなどの実機通信入口を制限する。メイン画面でUSBを許可しても、シミュレーションから実機へ接続しない。制限を設定できない環境ではシミュレーションを開始しない。これは多層防御であり、悪意あるコードを完全に隔離する保証ではない。

PWAへの追加は任意で、USB対応を新たに付与するものではない。インストール版でも同じAPI・OTG・許可・機器構成条件が必要で、実機未確認。USB接続・選択・転送中はアプリ更新を拒否する。利用者が明示的にUSBを切断してから更新する。[PWAの使い方](pwa.md)

Chrome公式では、AndroidでのUSBシリアル利用にWebUSBを使う方法が案内されている。ただしOSドライバなどが占有している機器には使えず、個々のスマホ・ファームウェアの保証ではない。[ChromeのWeb Serial: Polyfill](https://developer.chrome.com/docs/capabilities/serial#polyfill)

NanoC6の仕様・通常起動とダウンロードモードの区別は[M5Stackの公式資料](https://docs.m5stack.com/en/core/NanoC6)、native USB CDCとスリープ時の制約は[ESP32-C6 USB Serial/JTAGの公式資料](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c6/api-guides/usb-serial-jtag-console.html)も参照する。外部資料は2026-10-06に確認。これらの資料を本アプリのAndroid実機確認記録として扱わない。

## 実機受入の記録

スマホ機種、Android版、Chrome版、機器名、UIFlow2 / MicroPython版、USB VID / PID、ケーブル・ハブ・給電条件、通常タブ／インストール版、アプリのGit版を記録する。各項目は **PASS / FAIL / NOT RUN** と証拠（見守りログ、操作結果、実際の光・起動状態）を残す。現時点の実機結果は全項目 **NOT RUN**。

| 確認項目 | 合格条件 | 初期結果 |
| --- | --- | --- |
| 機器選択・許可 | タップ後にChromeの選択画面が出る。取消時に機器を操作しない | NOT RUN |
| 通常起動・REPL取得 | 自動実行中でも停止を試み、操作可能になる。ダウンロードモードを成功扱いしない | NOT RUN |
| main.py読み込み | 機器内の内容を取得し、日本語を含むコードが欠けない | NOT RUN |
| 安全なファイル転送 | サイズ・SHA-256・構文確認後に保存。構文エラー／転送中断を成功扱いしない | NOT RUN |
| 実行・再実行 | 実行開始を確認し、LED・ボタンの実動作を確認。再実行前に旧プログラムを停止 | NOT RUN |
| 自動実行ON／OFF | 対応版で保存値を確認。非対応版では変更せず案内 | NOT RUN |
| 再起動・再接続 | USB再列挙後に再接続し、保存値とコードを読み直せる。別機器を自動選択しない | NOT RUN |
| 電源再投入 | ON時に作品が自動実行し、OFF時は自動実行しない。保存コードは残る | NOT RUN |
| 抜線・給電不足 | 接続喪失を表示して操作を中止。旧処理が再接続後に勝手に再開しない | NOT RUN |
| 多重操作・PWA競合 | USB選択／接続／転送中に更新を拒否。二重接続で他の機器を操作しない | NOT RUN |
| OS占有・非対応USB | 他アプリの占有や対応外CDC構成を成功扱いせず、再接続／PC経路を案内 | NOT RUN |

本体のみの安全な読み込みから始め、給電・配線を確認してLED作品へ進む。意図的な給電不足や書き込み中の抜線は、重要コードを持たない検証用機器で行う。受入記録のない組み合わせを確認済みに変更しない。

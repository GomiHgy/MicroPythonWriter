# 任意の開発支援：運営者向け設定・公開手順

MicroPythonWriterの利用は無料です。支援の有無で機能は変わらず、支援による個別サポート・特定機能の実装・将来の開発継続を約束しません。支援導線は「開発を応援する」→説明ダイアログ→StripeまたはGitHub Sponsorsの外部ページだけです。アプリに決済フォーム、決済API、Webhook、支援者管理、追跡や特典開放を追加しません。

**初期設定は両方とも無効です。受付可能な支援先がなければ、入口・ダイアログ・空の領域も表示しません。** 実URL、受取設定、利用可否を確認しないまま公開フラグをONにしないでください。この文書やコードの完成は、実際の支援受付が開始した証明ではありません。

## 1. 公開前に判断すること

### Stripe：名称ではなく実際の受付内容を確認する

Stripeの日本向け禁止業種には「個人への寄付」が記載されています。「寄付」を「開発支援」「コーヒー代」に置き換えても、利用可能と判断できません。また、必要な特定商取引法の表記を掲載していない事業についても記載があります。[Stripeの禁止・制限業種](https://stripe.com/jp/legal/restricted-businesses)

運営者は、無料・機能制限なし・対価や特典の有無・受取主体・使途・単発／継続など、**実際の受付形態**とアプリの表示文言をStripeに説明して利用可否を確認してください。確認した対象、条件、日付、問い合わせの記録は運営者側で保持し、回答の条件が変わった場合は再確認します。確認前、回答が不明確な場合、認められない場合は無効のままにします。架空の商品、提供しないサポート、架空の購入特典を作って規約を回避しません。

`usageConfirmed` はこの確認を運営者が済ませたことを記録するフラグです。プログラムが法的適合性やStripeの承認を判定する仕組みではありません。コードのURL形式検証やテスト成功でも代替できません。

### GitHub Sponsors：ユーザー名だけでは受付準備完了にならない

GitHub Sponsorsでは単発と月額の支援を設定できます。「月額専用」と決めつけず、支払条件は対象プロフィールで確認します。[GitHub Sponsorsの概要](https://docs.github.com/en/sponsors/getting-started-with-github-sponsors/about-github-sponsors)

本人の対象プロフィール、受取に必要な設定、銀行・税務情報、2FA、申請の承認・公開状態を確認してください。`GomiHgy` は初期候補のユーザー名にすぎず、受付開始や本人確認の完了をアプリは推測しません。プロフィールが実際に支援を受け付ける状態になるまで `enabled: false` を維持します。[個人アカウントの受取設定手順](https://docs.github.com/en/sponsors/receiving-sponsorships-through-github-sponsors/setting-up-github-sponsors-for-your-personal-account)

GitHub Sponsors側でStripeを用いる受取設定があることと、運営者自身のStripe Payment Linkで今回の支援を受け付けられることは別です。一方の完了をもう一方の確認済みとして扱いません。

### GitHub Pages：外部決済リンクなら無条件に許可されるわけではない

GitHub Pagesには、商取引を主目的とするサイトや商用SaaSなどの利用制限があり、パスワード・カード番号等を扱う敏感な取引にも使用しない旨が示されています。今回は無料のツールを主目的として維持し、カード情報の入力は外部サービスに任せます。ただし、外部リンク方式だけで適合性を保証せず、実際のサイト・受付形態が制限に抵触しないか運営者が確認してください。判断に迷う場合はGitHubへ確認します。[GitHub Pagesの利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## 2. 設定場所と表示条件

編集箇所は [src/config/support.ts](../src/config/support.ts) の `supportConfig` です。利用者向けの支援先編集画面はありません。URLをクエリパラメータやブラウザのlocalStorageから変更する仕組みもありません。

| 設定 | 初期値 | 意味・公開条件 |
| --- | --- | --- |
| `github.enabled` | `false` | 対象プロフィールの受付開始を確認した場合だけON |
| `github.username` | `GomiHgy` | 対象GitHubユーザー名。形式を検証してSponsors URLを構築 |
| `stripe.enabled` | `false` | Stripeの入口を公開する意思。これだけでは表示されない |
| `stripe.usageConfirmed` | `false` | 実際の受付用途で利用可能と確認した場合だけON |
| `stripe.paymentLinkUrl` | 空文字 | 所有・本番状態を確認したPayment Link |
| `stripe.commercialDisclosureUrl` | 空文字 | 実際の事業者情報・取引条件を公開したHTTPSページ |

GitHubは `enabled` と妥当なユーザー名が揃うと表示対象になります。Stripeは `enabled` と `usageConfirmed` の両方がONで、決済URL・情報開示URLの形式も妥当な場合だけ表示対象になります。片方だけ有効ならその支援先だけを表示し、不正な設定はアプリ全体を停止させず、その支援先を非表示にします。

Stripeの初期対応はHTTPSの `buy.stripe.com` と完全一致するホスト・空でない決済パスです。類似ドメイン、危険なscheme、ユーザー名・パスワード付きURL等を使いません。独自決済ドメインは今回の対象外です。情報開示URLもHTTPSの妥当なURLを使います。**形式が通ることは、リンクの有効性・所有者・本番用・利用可能用途の証明ではありません。**

公開してよい情報だけを設定してください。APIキー、秘密鍵、Webhook署名鍵、銀行口座、カード情報は不要です。コード・ログ・機器識別子・利用者のメールアドレス・追跡IDをURLへ付加しません。

## 3. 具体的な公開設定例

### GitHub Sponsorsのみ公開する場合

以下は**受付開始の確認後だけ**使う例です。候補のユーザー名が本人の公開プロフィールと一致することを確認してください。Stripeは無効のままです。

```ts
export const supportConfig = {
  github: {
    enabled: true, // 受取設定・承認・公開状態を確認した後だけ
    username: 'GomiHgy', // 確認した実際の対象ユーザー名へ合わせる
  },
  stripe: {
    enabled: false,
    usageConfirmed: false,
    paymentLinkUrl: '',
    commercialDisclosureUrl: '',
  },
}
```

### Stripeのみ公開する場合

以下の `<...>` は**置換必須の説明用プレースホルダーで、実URLではありません**。そのまま本番設定へ貼り付けないでください。URLを差し込むだけでなく、用途の確認と情報開示を済ませてからフラグをONにします。既存ファイルの型やほかの定義は残し、設定値だけ変更してください。

```ts
export const supportConfig = {
  github: {
    enabled: false,
    username: 'GomiHgy',
  },
  stripe: {
    enabled: true, // 公開チェックを終えた後だけ
    usageConfirmed: true, // この実際の用途で利用可能と確認した後だけ
    paymentLinkUrl: '<所有・本番状態を確認したhttps://buy.stripe.com/のPayment Link全文へ置換>',
    commercialDisclosureUrl: '<実際の事業者情報・取引条件を公開したHTTPS URL全文へ置換>',
  },
}
```

両方公開する場合も、各サービスの確認を独立して済ませ、それぞれの `enabled` をONにします。未確認の一方をまとめて有効にしません。READMEには未公開の受付リンクを掲載せず、説明用ダミーURLも本番ファイルへ入れません。

## 4. Payment Linkと情報開示ページの準備

用途が認められると確認できた場合だけ、運営者がStripe DashboardでPayment Linkを作成します。初期案は単発の支援です。任意金額方式を選ぶ場合、推奨額・最低額などはDashboard側で設定します。方式の対応範囲も公式手順を確認してください。サイト側に金額入力や複数の価格ボタンは追加しません。[Payment Linksの作成手順](https://docs.stripe.com/payment-links/create)

公開時には、外部ページの受取先名、実際の説明、金額、通貨、単発／継続、追加費用や条件を確認します。アプリは金額・通貨・頻度を推測して表示せず、利用者に移動先で確認してもらいます。「コーヒー1杯分」の案内が実際の取引内容と矛盾する場合は、文言を運営者のレビュー事項として残してください。名称の言い換えを利用可否確認の代わりにしません。

情報開示ページには、実際の受付形態と適用要件に対応した事業者情報・取引条件・問い合わせ方法・必要なプライバシー説明を掲載します。氏名、住所、電話番号、返金・解約条件などを推測して作らず、公開方法に不明点があればStripeの案内や専門家へ確認してください。寄付控除、非課税、返金不可などを独自に断定しません。この運用文書自体は、実際の事業者情報・取引条件の公開ページを代替しません。

## 5. テスト：実際の課金はしない

自動テストでは設定値・URL・UI・処理中の抑止をローカルのモックで検証し、StripeやGitHubへ決済リクエストを送りません。

```powershell
npm run check:locales
npm run lint
npm test
npm run build
```

ビルドに含まれるライセンス確認・PWA確認を無効化して通さないでください。既存由来の失敗と変更由来の失敗を区別し、ブラウザや外部サービスで未確認の項目を自動テストの成功で置き換えません。

ブラウザの確認は未公開のローカル環境で行います。初期無効、本番URL未設定、片方だけ有効、不正URL、処理中などを試し、確認用のフラグ・テストURLを本番へ混入させないでください。Stripeの決済確認が必要なら、運営者がテストモード／Sandboxのリンクと公式テスト用情報を使い、実カードや本番モードで試験課金しません。[Stripeのテスト手順](https://docs.stripe.com/testing)

支援画面だけを確認する場合は、`npm run dev` の起動後、ローカルの `/src/test/fixtures/support-browser.html` を開きます。これは開発サーバー専用の確認画面で、公開設定を変更せず、両サービス・処理中・言語・テーマを試せます。架空のテストURLを表示しますが、すべての外部リンクのクリックを抑止します。この画面から支援を確定したり、外部ページの有効性を確認したりはできません。通常の `npm run build` の配信物には含まれません。実アプリでは、両サービスOFFのまま入口が出ないことも別途確認してください。

GitHub Sponsorsはプロフィールの公開状態・受取設定・リンク先・支援選択肢を確認する範囲に留め、動作確認のために支援を確定しません。外部ページから戻ったこと、クリック、`success=true` などをアプリが「決済成功」と扱わないことも確認してください。

設定変更はバンドルへ埋め込まれるため、**再ビルドと公開が必要**です。Dashboardの確認だけで現在のアプリ表示が切り替わるわけではありません。

1. 作業ブランチで設定値と表示を確認し、上記の自動テスト・ローカルのブラウザ確認を行う。
2. 変更差分をレビューし、運営者の明示的な公開判断を受ける。今回の実装作業はmainへの直接push・マージ・リリースや本番外部サービス設定を実行しない。
3. 公開が承認された後、既存のGitHub Pages公開手順でレビュー済みビルドを配信する。`base` やサブパス構成は変更しない。
4. 公開ページのバージョンを確認し、設定した支援先だけが表示され、未確認の支援先が隠れていることを確認する。実課金はしない。
5. PWAでは安全な更新手順も確認する。モバイルで外部ページへ移動してもUSB/BLE接続が必ず維持されるとは保証しない。

## 7. 支援受付を停止するとき

**アプリの非表示化と外部サービスの受付停止は別です。** 古いPWA・開きっぱなしのタブ・共有済みリンクには、更新前のURLが残る場合があります。

1. 運営者が外部サービス側で受付を止める。StripeのPayment LinkはDashboardから無効化できます。GitHub Sponsorsは対象プロフィールの受付状態・既存の継続支援への扱いを公式案内で確認し、必要ならGitHubへ相談する。[Stripeのリンク無効化手順](https://docs.stripe.com/payment-links/share#deactivate-a-link)
2. アプリの対象 `enabled` を `false` にし、用途確認が失効したStripeは `usageConfirmed` も `false` にする。必要なレビューの後に再ビルド・公開し、入口が非表示になったことを確認する。
3. README、公開ドキュメント、プロフィール、QRコード等の案内を個別に確認する。外部リンクを無効化するだけで、既存の継続支援・返金・解約の処理まで完了したと判断しない。
4. `.github/FUNDING.yml` やアカウントの既定支援設定があれば別途確認する。**Webアプリの `enabled=false` は、リポジトリのSponsorボタンやFUNDINGのリンクを無効にしません。** ほかの既存支援先を無断で削除・置換しない。
5. 古いPWAの更新と、外部の古いリンクから新しい支払いを開始できないことを確認する。アプリ側のキャッシュ削除だけに頼らない。

本作業では `.github/FUNDING.yml` を新設・変更しません。受付開始を確認した後に設定する場合は、GitHub Sponsorsの形式は `github: GomiHgy`（対象ユーザー名に合わせる）、Stripe等の外部URLは `custom` です。実URLと受付用途の確認後だけ掲載し、既定ブランチでの公開も別の承認された作業として扱います。[GitHubのFUNDING設定](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/displaying-a-sponsor-button-in-your-repository)

## 8. 今回の実装と運営者に残る作業

コード・自動テストで扱えるのは、表示条件、URLの形式、安全な外部リンク、状態を壊さないダイアログ、多言語表示、処理中の抑止などです。外部の本人確認・銀行税務情報・用途承認・本番リンクの所有や受付状態・実際の情報開示は運営者の作業です。

未準備ならフラグをOFFに保ったままアプリを利用できます。支援を受け付けるために本来のLED・AI・USB・BLE機能を制限しません。自動テストPASS、ブラウザ検証、機器検証、外部サービス確認、公開反映を分けて報告してください。

公式資料の確認日：2026-10-07。規約・Dashboardの表示や対応範囲は変更される場合があるため、実際の受付開始・変更・停止時にも最新の公式案内を確認してください。

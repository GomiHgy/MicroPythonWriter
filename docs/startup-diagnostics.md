# 起動クラッシュの診断とUSB操作の復旧

## 何を調べる機能か

USBの転送・構文確認が成功しても、作品の起動後にファームウェア内部でクラッシュして再起動する場合がある。例えば `Guru Meditation Error` は通常のPython例外とは別で、Pythonの終了応答が届かないことがある。

Webアプリは常駐プログラムの出力中の `A fatal error occurred. The crash dump printed below`、`Guru Meditation Error: Core ... panic'ed (...)`、`ESP-ROM:esp32...`、`MPY: soft reboot` を、分割されたUSBデータから検出する。異常終了として実行中表示を解除し、古い常駐セッションを破棄する。停止操作中でも正常停止にしない。機器への保存が確認済みなら書き込み成功は保持する。

クラッシュ後の新しい書き込み・実行・リセットはRaw REPLの明示的な再取得まで拒否する。自動再実行・自動リセット・自動起動設定変更は行わない。検出はシリアル文字列によるもので、機器内部の監視や原因の特定ではない。同じファームウェア出力を作品が意図的に行った場合は区別できない。また、通信が先に失われてログが届かない場合はUSB切断の案内になる。

## 利用者の手順

「プログラム」画面の下部にある **起動時に再起動する場合の診断（必要なときだけ）** を開く。通常は閉じている。
本体の異常終了を検出した場合は、操作結果の **エラーの詳細・対処を見る** から診断欄を開ける。

1. **元コードを保存** を押し、`main-original.py` がダウンロードできたことを確認する。元コードを別ファイルに保管した確認にチェックする。ダウンロード開始だけでは保存完了の証明にならない。
2. **診断版を保存** で `main-diagnostic.py` を保存する。書き出し自体はエディタ・機器を変更しない。
3. 元作品のバックアップがある状態で、診断版の全文をコード欄へ貼る。機器の電源を完全に切って入れ直し、USB接続して **実行** を1回だけ押す。本体ボタンやBLEを操作しない。
4. 起動・異常終了のログが出たら **診断ログを保存** で `MicroPython-diagnostic-log.txt` を保存する。アクセスコード・Wi-Fi情報・資格情報などを確認し、共有前に必要に応じて伏せる。ログは自動送信しない。
5. 診断後は保管した元コードをコード欄へ戻す。機器へ戻す操作も利用者が明示的に行う。

**実行は機器のmain.pyを上書きする。** 自動実行がONなら次の電源投入時にも診断版が動く。診断ファイル作成では起動設定を変更しない。機器内の `.bak` は次の書き込みで変わるため、それだけを原本保管先にしない。

## 診断版が追加すること・しないこと

- 元の文・コメントを置換せず、構文木で特定できる文の前後に `[MPW DIAG NN] ... BEFORE / AFTER` を挿入する。複数行の引数とインデントを維持する。module docstringとfuture importも維持する。
- ハードウェアimport、Pin、bitstream、BLE構築・有効化・MTU/GATT/広告の設定、対応する作品の初期化・最初の更新を対象にする。同じログ地点は最初の1回だけ記録する。最大32文を対象にし、ループごとの無制限出力を避ける。
- Pythonの使用量・空き量とESP-IDFのヒープ領域の `(総量, 空き, 最大空きブロック, 過去の最小空き)` を別々に記録する。APIがなければ `unavailable`。両者を合算しない。
- 構文エラー・診断用変数名との競合では生成しない。一行suiteやセミコロンで並べた文などは変更せず、対象数・省略数を表示する。任意のalias・動的API呼び出しをすべて追跡するものではない。
- GPIO・LED数・最大輝度・演出・引数・無線の設定を変更しない。Wi-Fi停止・BLE先行有効化・GC強制回収・リセット・追加sleepを対策として加えない。

ログ関数・観測モジュールの読み込み・計測自体がメモリ使用量やタイミングを変える。BEFOREとAFTERが揃わない地点は調査の手掛かりであり、そのAPIが原因であるとの証明ではない。診断版が動いても元作品の問題解消や提供側の実機確認済みにはしない。正確なネイティブ関数の特定には対象ファームウェアと一致するELFが必要。
番号はソース内の位置を示すため、分岐・例外処理・後始末では番号順に出ない場合がある。

## 異常終了した後の操作

起動ログが落ち着いてから **USB操作を復旧する** を押す。作品の停止を試してRaw REPLを再取得し、機器情報を読み直す。コードや自動起動設定は変更せず、作品を再実行しない。失敗する場合は **接続を切る → 電源を入れ直す → USBをつなぎ直す**。繰り返し再起動する場合は既存の電源投入時の復旧ガイドを参照する。

## 検証範囲

ホストテストで分割panic・ROM起動ログ、停止中の再起動、終了通知、古いセッションの破棄、同期前の書き込み禁止、診断版の構文木比較とAPI順序、保存・保管確認UI、9ロケールの案内を確認する。実機のメモリ値・クラッシュ解消・Android USB/BLEの動作は **NOT RUN**。対象作品での診断実行と、原因に応じた修正後の実機確認が別途必要。

# インストールして使う（PWA）

公開ページを、ホーム画面やパソコンのアプリとして追加できる。インストールは任意で、今まで通りブラウザのタブでも使える。

## 追加する

1. 初回はネットにつないで、HTTPSの公開ページを開く。
2. 「アプリとして使う」の「ホーム画面・パソコンに追加」を押す。
3. ボタンがない場合は、Chrome / Edgeのブラウザメニューから「アプリをインストール」を選ぶ。iPhone / iPadのSafariでは、共有メニューの「ホーム画面に追加」を使う。メニューの名前や、追加できる条件はブラウザによって異なる。

追加後も機器への接続は毎回利用者が選ぶ。USB / Bluetoothを勝手につないだり、保存コードを勝手に実行したりしない。

PWA化そのものでは機器通信の対応範囲は増えない。USBはパソコン版Chrome / EdgeのWeb Serialを優先する。AndroidではWebUSBが使えればWeb Serial APIの有無によらずWebUSB CDCを優先し、WebUSBがない場合はWeb Serialを使うがUSB機器の列挙は端末対応次第。それ以外はWeb Serial、Web SerialがなければWebUSB CDC fallbackを使用する。USBホスト（OTG）対応AndroidスマホのChromeからM5NanoC6を操作する経路は実装済みだが、通常タブ・インストール版とも接続成功は実機未確認。[Androidの接続条件と手順](android-usb.md)を確認する。Web Bluetoothは対応するパソコン・AndroidのChromeなどを使用する。iPhone / iPadのSafariに追加しても、このアプリのUSB / Web Bluetooth機能は利用できない。シミュレーターには従来通りWebAssembly JSPI対応も必要。[ChromeのWeb SerialとAndroidのWebUSB利用](https://developer.chrome.com/docs/capabilities/serial#polyfill)、[Web Bluetooth](https://developer.chrome.com/docs/capabilities/bluetooth)

## ネットなしで使う

- 「基本画面をオフライン用に保存しました」が表示された後は、次回からネットなしでも画面を開き、コードの編集、準備文の生成、保存済みプログラムを利用できる。
- AIサービスとの対話、ファームウェア書き込みサイトなどの外部サイトにはネット接続が必要。
- シミュレーターは初期保存に含めない。「インストール・オフラインの使い方」を開き、「ネットなしでも試せるように保存」を押すと、Pyodideとその版の原本情報をまとめて保存する。現行版は計12,284,211 bytes（約12.3MB）。全ファイルの取得・SHA-256照合・保存が完了してから「保存済み」と表示する。
- 未保存のシミュレーターはオンラインで使用できるが、単に再生しただけではオフライン保存完了として扱わない。ネットなしで試したい場合は上記の保存ボタンを使う。
- 「オフライン用データを削除」は、**現在のシミュレーター版**のキャッシュだけを削除する。コードや保存済みプログラム、機器設定は削除しない。

初回の準備・保存が途中で失敗した場合は、オフライン利用可能とは扱わない。保存容量や通信を確認して再試行する。

## アプリを更新する

1. 「新しいバージョンがあります」が表示されても、自動では再読み込みしない。作業を続けられる。
2. USBとBluetoothの接続を切り、シミュレーションを一時停止する。機器が自動実行を続けている場合、アプリ更新はその作品を停止する操作ではない。
3. 必要なAI詳細設定は「このブラウザに設定を保存」で保存する。編集中の保存フォームの名前・説明、ログ、シミュレーションの状態は再読み込み後に引き継がれない。必要な内容は別途退避する。
4. 同じアプリを開いている他のタブ・ウィンドウを閉じ、「更新して開き直す」を押す。
5. 確認ダイアログで了承すると、編集中コード・作品の下書き・表示設定を同期保存し、読戻しを確認してから更新する。保存失敗・未適用のAI設定・保存作品の読み込み異常がある場合は更新を中止する。

更新準備中は画面の編集を無効化し、新しいUSB / Bluetooth接続とシミュレーション開始・再開も拒否する。更新の待機ワーカーから成功応答を受け、活性化が完了した場合だけ、操作した画面を再読み込みする。別のタブでの更新通知だけでは再読み込みしない。

更新でシミュレーターの必要な版が変わった場合は、その版を改めてオフライン保存する。変更のない同じVM版は再利用する。

AndroidでUSB接続方式を修正した版を使う場合も、この手順で更新してから接続をやり直す。ページ下部のアプリ版を確認し、ネイティブのUSBシリアルアプリは接続を切って終了する。[USB機器選択画面の再確認手順](android-usb.md#修正版で選択画面を再確認する)を参照する。

## 保存とプライバシー

アプリのキャッシュには、公開ビルドの画面・アイコン・ライセンスと、利用者が希望した場合だけシミュレーターを収録する。ユーザーのコード・シリアルログ・BLEの操作や状態、AIへの送信内容はService Workerで収集・キャッシュしない。作品や設定の保存は既存のブラウザ内保存機能のままで、サーバーや他の端末に自動共有しない。

保存領域は同じオリジン内だが、ブラウザ・OSによって通常タブとインストール版の保存領域が共有されない場合がある。別のブラウザや端末に移す前には、コード・作品ファイルを書き出す。

ブラウザの容量整理、サイトデータ削除、プライベートモード、アンインストールなどで保存データを失う可能性がある。オフライン保存は永久的なバックアップではない。大切なコードはファイルにも保存する。[ブラウザのオフラインデータと保存領域](https://web.dev/learn/pwa/offline-data)

旧版を開いたページを壊さないよう、Service Workerは過去の版のキャッシュを自動削除しない。このため更新を繰り返すと使用容量が増える。サイトデータを全削除して整理する場合は、**保存済みプログラム・設定も消える**ため、先に必ずファイルへ退避する。他のアプリのキャッシュやlocalStorageを削除するコードは含めない。

## 開発・検証

`npm run dev`では新しいService Workerを登録しない。通常の開発に古いオフライン画面が混ざらないよう、本番ビルド専用とする。

```powershell
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

localhostはブラウザの安全なコンテキストとして検証できる。公開先はHTTPSが必要。既存のGitHub Pagesワークフローは`dist`全体を配信するため、別の配信サービスやバックエンドは不要。manifestの`id` / `scope` / `start_url`、アイコン、Service Workerは相対パスで、`/MicroPythonWriter/`配下と独自ドメインのルートに対応する。

Service Workerはビルドの実内容ハッシュで版管理する。`npm run build`の最後にPWA成果物も検査し、manifest・アイコン・キャッシュ一覧・SHA-256・版が実ファイルと一致することを確認する。再検査は`npm run check:pwa`。配信途中に新旧ファイルが混ざった場合は、SHA-256照合に失敗した版を有効化せず、既存の版を保つ。任意のURL、外部AI、POST、アプリのscope外の要求をキャッシュしない。ライセンス全文は基本画面と一緒に保存する。

参考：[Service Workerのライフサイクル](https://web.dev/articles/service-worker-lifecycle)、[利用中のPWAの更新](https://web.dev/learn/pwa/update)、[Viteの相対base](https://vite.dev/guide/build)。

### 公開後・実機の確認項目

- パソコンChrome / Edge、Android Chromeでインストールと単独ウィンドウの起動。
- iPhone / iPadの追加手順と、使えない機器通信の案内。
- 初回オンライン準備後にブラウザを終了し、オフラインで再起動・コード編集・保存済みプログラムの読込み。
- 任意保存後のオフラインシミュレーション。未保存時・容量不足時の失敗表示。
- GitHub Pagesのサブパスでmanifest / アイコン / SW / VMが同じアプリの配下になること。
- 旧版を開いたまま新版を配信し、勝手に再読み込みしないこと。USB / BLE接続中、転送中、シミュレーション中、複数窓で更新が拒否されること。
- Androidの通常タブとインストール版で、USB接続・選択中・転送中に更新が拒否されること。抜線／再起動の後に接続先を選び直せること。機種・Android / Chrome / UIFlow2版付きで[USB受入記録](android-usb.md#実機受入の記録)を残し、PWA化をUSB動作保証の代わりにしない。
- 確認して更新した後、コード・保存済みプログラム・設定が残ること。保存失敗時に再読み込みしないこと。

自動テスト・ビルドの成功は、実機接続・OSへのインストールや公開先での動作確認とは区別する。

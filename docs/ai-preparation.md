# 「AIの準備」設定・開発者ガイド

## 利用者の操作

1. 「AIの準備」を開き、使うM5NanoC6／AtomS3Liteを選ぶ。
2. UIFlow2をまだ書き込んでいない場合は、機器に対応するM5Burnerの案内を開き、**UIFlow2.0** を選んで手動で書き込む。書込み済みなら次へ進む。
3. このアプリで、実際に書き込んだUIFlow2ファームウェアの版を入力し、LEDの型番を選ぶ。LED数・最大輝度・外部LEDピンも実物に合わせ、「AIに渡す準備文をコピー」を押す。
4. 好きなAIの新しい会話へ1回貼り付け、自分で送信する。
5. AIの質問に答え、整理された仕様を確認して「この仕様で作って」と依頼する。
6. 完成した `main.py` をWriterの「プログラム」へ貼り付けて「実行」する。

ファームウェアの案内先は、M5NanoC6なら [M5Burner / NanoC6](https://burner.m5stack.com/device/nanoc6)、AtomS3Liteなら [M5Burner / AtomS3 Lite](https://burner.m5stack.com/device/atoms3-lite)。選択機種に応じたページを開き、UIFlow2.0の書込みが完了したらM5BurnerのUSB接続を切って、このアプリへ戻る。機器内のプログラムや設定が消える可能性があるため、必要なコードを先に保存し、WriterやほかのアプリのUSB接続を切ってからM5Burnerで接続する。このアプリはファームウェア書込みの自動実行、M5Burnerへのコード送信、ファームウェア版の自動入力を行わない。

キットIDの割り当てや講師の事前設定は不要で、自宅でも利用できる。ファームウェア版とLEDの型番は推測せず、書き込んだ版や購入品の仕様を確認して入力する。設定した値は準備文へ入るため、AIとの会話で再入力する前提にしない。相談は1回1問・選択肢3〜5個・最大6問。十分な仕様と明確な生成依頼がある場合は不要な質問を省略できる。

AIの準備はUSB接続を必要としない。既存ユーザーは直接「プログラム」を使用できる。タブ切替でUSB/BLEを切断したり、実行中のプログラムを止めたりしない。選択できるAIはChatGPT・Claude・Gemini・[DeepSeek](https://chat.deepseek.com/)。リンクを開くだけではコピーも送信も行わない。他のAIにも同じ準備文を手動で貼れる。

画面上部の言語選択は **日本語／English／简体中文（簡体字中国語）**。画面の案内、準備文、修正依頼の説明を切り替え、ブラウザに選択を保存する。言語変更では選択機器・未適用設定・確認者名・接続・実行状態をリセットしない。コード、基準コード、ログ、機器からの原文、利用者が入力した表示名などは自動翻訳しない。日本語で入力したデータが英語画面に残るのは意図した動作である。

## 配布プリセット

正本は [src/config/workshops.ts](../src/config/workshops.ts)。`workshopPresets` は `{ id, profile }` の配列。`id` は保存先を識別する固定キーであり、利用者が入力する番号ではない。`materialId` も保存互換性のための内部識別子として維持する。利用者向けのキットID仕様は設けない。

配布時は `nano-c6-led-default`（M5NanoC6）と `atom-s3-lite-led-default`（AtomS3Lite）を用意する。両方ともLED数10・最大輝度20%・外部LEDピン2が初期値。UIFlow2版は未入力、LED型番は未選択とし、推測の値を入れない。利用者は「AIの準備」の通常表示で5項目を入力・選択でき、有効な入力は機種別に自動保存する。機種別の設定やBLE確認を自動で使い回さない。

構造例（`id` / `materialId` は内部キーであり、利用者に入力させない）：

```typescript
export const workshopPresets: WorkshopPreset[] = [
  {
    id: 'my-nano-c6-profile',
    profile: {
      ...sharedProfile,
      boardId: 'm5nanoc6',
      features: { ...sharedProfile.features },
      baseline: { code: '', verification: null },
    },
  },
  {
    id: 'my-atom-s3-lite-profile',
    profile: {
      ...sharedProfile,
      boardId: 'atoms3lite',
      materialId: 'atom-s3-lite-led-workshop',
      displayName: 'AtomS3Lite',
      features: { ...sharedProfile.features },
      baseline: { code: '', verification: null },
    },
  },
]
```

共通設定 `sharedProfile` に初期値・固定条件を定義し、実物に依存する未確定値は利用者が入力する。

| 項目 | 記入・検証条件 |
| --- | --- |
| `boardId` | `m5nanoc6` または `atoms3lite`。機種と固定ピンを選ぶ。「使う機器」で切り替える |
| `materialId` / `revision` | 教材識別子・Writerの設定版。UIFlow2の版とは別。安全な英数字等で設定 |
| `displayName` | 利用者が見分ける表示名。既定値は機種名 |
| `firmwareVersion` | 対象UIFlow2の正確な版を利用者が入力し、自動保存する。USBから取得したMicroPython版やfirmwareInfoで推測しない |
| `ledModel` | 利用者が WS2812B / WS2812B-MINI / WS2812C-2020 / SK6812 / SK6812MINI から選び、自動保存する |
| `ledCount` | 実際のLED個数。初期値10、正の整数。通常画面で変更・自動保存する |
| `ledPin` | 外部LEDピン。初期値2。通常表示で利用者が変更・自動保存。0〜48の整数は形式チェックのみで、実配線・機器で出力可能かは別途確認する |
| `ledBpp` | 3（RGB）固定。設定画面には表示しない。SK6812系を選んでもRGBW（4）へ自動対応・変換しない。実物のチャンネル数を確認する |
| `maxBrightnessPercent` | 初期値20%。利用者が電源と実機を確認して入力・自動保存する上限。有限数・0超100以下。範囲に入るだけでは安全の証明にならない |
| `features` | `button`、`ble`、`controller` の利用希望 |
| `baseline` | 基準コード全文と、その内容・対象機種・対象版に結び付く実機確認記録 |

未確定値は `null` にする。未設定や未解決の `{{...}}` を含む利用者向け文面は出力させない。型番の選択だけで実機適合を保証しない。機種ごとのボタンピン、bitstream encoding=0・800kHz用タイミング、GRB順、200msのフェード条件は設定画面で変更できる項目にしない。

### 機種別の配線

| 機種 | 外付けLEDの初期値 | ボタン（active LOW） | 内蔵RGB | その他の内蔵LEDピン |
| --- | --- | --- | --- | --- |
| M5NanoC6 | Grove G2 / GPIO2 | GPIO9 | GPIO20 | RGB電源 GPIO19、青色LED GPIO7 |
| AtomS3Lite | Grove G2 / GPIO2 | GPIO41 | GPIO35 | NanoC6のGPIO19・GPIO7制御は不要。流用しない |

定義の正本は [boards.ts](../src/config/boards.ts)。[M5NanoC6公式資料](https://docs.m5stack.com/en/core/M5NanoC6) と [AtomS3 Lite公式資料](https://docs.m5stack.com/en/core/AtomS3%20Lite) に照らして配線する。外付けLEDと内蔵LEDを同じものとして扱わない。SoCがESP32-S3というだけではAtomS3Liteと確定できない。

BLEの名前は確認済み基準コードの実際の名前を維持する。`NanoLED-` 接頭辞は後方互換のため変更しない。新しい名前を明示的に設定する必要があるときの例は `NanoLED-M5NanoC6` / `NanoLED-AtomS3Lite`。これは一意なIDではなく、同名が複数あり得る。自分の機器の電源で出現・消失を確認して見分ける。設定変更で基準コード中の名前を自動書換えしない。

## 利用者の機器・LED設定と保存

機器選択の下でUIFlow2ファームウェア版・LED型番・LED数・最大輝度・外部LEDピンを編集する。「詳細設定」を開いたり適用ボタンを押す必要はない。他の不足項目があっても、有効な入力をブラウザへ自動保存する。保存キーは機種・プリセット・設定版に紐付く。保存拒否や破損は通知し、不正な入力で直前の保存値を上書きしない。ほかの詳細設定と基準コードの保存は従来どおり明示操作のみ。

対象UIFlow2版・LED条件を変更すると、その条件で確認されていない基準コードの実機確認登録を失効させる。新しい値は3言語の準備文・修正依頼にも反映するが、過去のエラーの操作時スナップショットは変更しない。基準コード本文や実行中プログラムを自動で書き換えない。ボタンと内蔵LEDの機種別ピンは変更しない。

失効状態も `verificationInvalidated` として保存する（コード本文はこの自動保存に含めない）。設定をA→B→Aと戻して再読み込みしても古い実機確認を復活させず、実機で再確認し、コードと確認情報を明示的に保存した場合だけ復元後も有効になる。

## ブラウザ内の詳細設定

「詳細設定」で表示名・使用機能・BLE基準コードなどを設定する。機種・内部の設定識別子・設定版は配布プリセット由来であり、更新時はリポジトリ側を変更する。対象機器・現在の外部LEDピン・固定の内蔵ピンは詳細設定内にも読み取り専用で表示する。機種を変えるときは「使う機器」で選び直す。詳細設定の編集を適用しても、Writer内の編集中コード・機器情報・接続を変更しない。

未適用の変更または基準コードの読込み待ちがある間は、古い準備文のコピー・保存・プレビューを止める。読込み後に「設定を適用」してから利用する。既に実行したプログラムのエラー文脈は、その実行時の設定を保持する。

基準コードはテキスト欄または `.py` ファイルから登録できる。読み込みはデータとして行い、JavaScript/MicroPythonとして実行しない。コード本文は100000文字まで。長すぎるものは黙って切り詰めず、登録できないことを表示する。

コードを対象機種・対象ファームウェアで実機確認した場合に限り、確認者名などを添えて確認を登録する。自宅利用でもこの確認要件を省略しない。新規登録は `verification.boardId` も記録する。アプリのテスト結果で実機確認済みとすることはない。コードまたは対象UIFlow2版・LED条件を変更すると確認を失効させる。別機種の確認記録は有効にせず、機器の切替でも確認記録を移さない。

BLE基準コードがない、未確認、対象版が違う場合はBLEを利用不可にする。Webコントローラには追加でNanoLED v1またはv2の確認とRGB・1〜300LEDが必要。再生・停止・作品ごとのモード／アクションはv2専用で、詳細設定のv2確認項目を実機確認後に明示登録する。LED・ボタン設定が有効なら、その部分の相談は続けられる。

実機確認記録は従来の `nanoLedV1: boolean` に任意の `nanoLedV2: boolean` を追加する。旧保存データの省略をtrueとして補わない。v1だけなら従来ルールを生成し、v2が明示確認されているときだけ3言語のv2ルールとカタログ・再生・アクション仕様を含める。修正依頼も同じ共有ルールを使用する。v1で未対応の操作を利用可能と案内しない。v2登録は自己申告記録であり、アプリの自動テストによる実機認証ではない。

折りたたみUIは誤操作を減らすためであり、認証・アクセス制御ではない。原典と確認済み基準コードに矛盾がある場合、AIへ勝手な補正を依頼せず実機と資料で確認する。未確認のBLE基盤はこの機能で新規開発しない。

## 保存・復元と教材更新

通常画面の5項目は自動保存する。ほかの詳細設定をブラウザへ保存する操作は明示的に行う。基準コードは通常メモリ上だけにあり、基準コードも保存する場合だけ利用者が明示的に選ぶ。内部の設定識別子・版・プリセットID・対象機種が一致するデータだけを復元し、型・内容も再検証する。旧版データや壊れたデータを現在版へ黙って混ぜない。

旧保存データの `kitId` は利用者向け仕様の廃止に伴い破棄し、他の有効な設定を維持する。既存のLED型番が選択肢の5型番と一致しない場合は推測で読み替えず、再選択を案内する。過去のLED数・最大輝度・外部LEDピンは有効なら維持し、外部LEDピン導入前の旧設定には従来値GPIO2を補う。

機種識別子導入前の互換処理は、プリセットID `nano-c6-led-default`、教材ID `nano-c6-led-workshop`、設定版 `writer-ai-1` が一致し、`boardId` だけが存在しない旧設定に限り `m5nanoc6` を補う。機種不明の任意設定やAtomS3Liteへ移行しない。旧確認情報の機種省略もNanoC6でのみ有効とし、AtomS3Liteは機種を明示した実機確認を新たに登録する。言語設定 `mpw-language` は教材設定とは別に保持する。

保存機能が拒否された場合や容量超過の場合は、保存できなかった旨を表示する。現在のメモリ上の設定と通常の操作は続けられる。編集中のユーザーコード・シリアルログはAI準備の保存領域に入れない。Writerが以前から持つ編集コード等の保存とは別の領域で管理する。

教材・共通条件・プリセット構成を更新し保存互換性が変わる場合は `revision` を更新する。新しい配布版の初期設定を確認し、必要なら新しい版に対して再設定・再確認する。`writer-ai-1` は初期実装の設定版で、UIFlow2のバージョン番号や実機検証の認証ではない。

## コピー・ファイル保存で困ったとき

プレビュー、コピー、UTF-8 `.txt` 保存は同じ生成済み文面を使用する。保存ファイル名は `MicroPython-${boardId}-${revision}-AI-preparation.txt` とし、キット番号を含めない。コピー成功はクリップボードのPromise成功後にだけ表示する。拒否・未対応ならプレビューの読み取り専用欄を選択し手動コピーする。準備文には長さによる自動省略や分割を行わない。

10秒待ってもコピーが完了しない場合は、成功と表示せず手動コピーを案内する。ブラウザ側の書込み処理自体を取り消すAPIではないため、後からクリップボードへ反映される可能性はある。成功通知は [Clipboard.writeText の完了Promise](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText) に基づく。

基準コードを含む文面全体に秘密情報らしき代入が見つかった場合、コピーもファイル保存も確認してキャンセルできる。自動検出は補助であり、完全ではない。コードのコメント等に意図しない個人情報・秘密情報がないか、利用者が確認する。

WriterはAPIキーを要求せず、自動でAIへ送信しない。利用者が各AIへ貼って送信した時点で、その内容は各サービスに渡る。保存してもAIの入力上限やコンテキスト消費が減るわけではない。特定の有料プランを必須とせず、無料・無制限とも保証しない。

## 原典と実行時テンプレートの対応

[prompt.md](../prompt.md) は教材原典として残す。実行時はMarkdownの見出しを切り出さず、以下の明示的な型付き設定とテンプレートを使用する。

| 原典・要件 | 実行時の担当 |
| --- | --- |
| Aの機器・LED設定・実機確認情報 | `WorkshopProfile.ts` / `src/config/workshops.ts` |
| 機種・内蔵LED・ボタンの違い | `src/config/boards.ts` / プリセットの `boardId` |
| AのLED・ボタン・bitstream・GRB・最大輝度・200msの条件 | `WorkshopRules.ts` の共通ルール |
| AのBLEと0.3・[NanoLED v1/v2仕様](ble-protocol.md) | 共通ルール。利用可能な版の実機確認に従いコード全文と該当仕様を含む。v1から自動昇格しない |
| A末尾の返答とBの相談手順 | `StartPromptBuilder.ts`。準備完了の挨拶だけを要求せず、最初の質問1問を開始 |
| Hの静的チェックと実機確認の区別 | 初回文・共通ルール |
| エラー相談 | `RepairPromptBuilder.ts` が同じ共通ルールを使用。`useProgrammer` が操作・実行時の文脈を保持 |
| 保存データの復元・版照合 | `WorkshopStorage.ts` |
| コピー・ファイル保存 | `PromptExport.ts` / `AiPreparationPanel.tsx` |
| UIと生成文の言語 | `src/i18n/` / 各PromptBuilderの言語別テンプレート |

初回文にエラーテンプレート、E0、課題集、Writerの編集中コード・ログを無条件に混ぜない。教材の「UIFlow2コードモードへ貼る」は「UIFlow2ファームウェア上でWriterのRaw REPLから実行する」に置き換える。共有ルールは複数Builderへ長文を複製しない。

エラー修正では、エラー対象の操作・実行に対応するコードと機器・LED設定を使用する。後で編集・機器変更しても古いエラーの依頼文を最新版へ差し替えない。実行コードを取得していない機器操作は未取得・対応未確認と明示し、エディタの内容を機器で実行済みと仮定しない。選択中の設定が不正なら不正と示し、通常用の汎用設定へ黙って置き換えない。

言語を変えると修正依頼の説明は再生成するが、エラー時のコード・ログ・機器情報・設定は同じスナップショットを使用する。実機の検出機種と選択機器が異なる場合は不一致を明示し、機種と配線を確認するまでGPIO依存の修正版を確定させない。

## 確認範囲

`npm run lint`、`npm run test`、`npm run build` で検証する。型・値・プレースホルダ、BLE確認の失効、共有ルール、エラー文脈、コピー・保存とプライバシー、保存不可・破損・旧版、既存タブと接続の保持を個別に確認する。

自動テストやブラウザ内の模擬操作は、実機の発光・無線・USB動作や、外部AIの応答を保証しない。外部AIへの実貼り付け、USB/BLE実機、電源とLEDの安全性は別の受入確認であり、未実施なら `NOT RUN` と記録する。

# 「AIの準備」講師・開発者ガイド

## 参加者の操作

1. 「AIの準備」を開き、講師から指定されたキットを選ぶ。
2. 「AIに渡す準備文をコピー」を押す。
3. 好きなAIの新しい会話へ1回貼り付け、自分で送信する。
4. AIの質問に答え、整理された仕様を確認して「この仕様で作って」と依頼する。
5. 完成した `main.py` をWriterの「プログラム」へ貼り付けて「実行」する。

質問は1回1問・選択肢3〜5個・最大6問。準備文には必要な設定が入るため、GPIO・UUID・ファームウェア版などを参加者が調べたり再入力したりする前提にしない。十分な仕様と明確な生成依頼がある場合は不要な質問を省略できる。

AIの準備はUSB接続を必要としない。既存ユーザーは直接「プログラム」を使用できる。タブ切替でUSB/BLEを切断したり、実行中のプログラムを止めたりしない。AIのリンクを開くだけではコピーも送信も行わない。

画面上部の言語選択は **日本語／English／简体中文（簡体字中国語）**。画面の案内、準備文、修正依頼の説明を切り替え、ブラウザに選択を保存する。言語変更では選択キット・未適用設定・確認者名・接続・実行状態をリセットしない。コード、基準コード、ログ、機器からの原文、講師が入力した教材名などは自動翻訳しない。日本語で入力したデータが英語画面に残るのは意図した動作である。

## 配布プリセット

正本は [src/config/workshops.ts](../src/config/workshops.ts)。`workshopPresets` は `{ id, profile }` の配列。`id` は保存先を識別する固定キーで、参加者が選ぶキット番号とは別にする。同じ教材の複数キットで共通値を共有し、キット番号など必要部分だけ変えられる。

配布時は `nano-c6-led-default`（M5NanoC6）と `atom-s3-lite-led-default`（AtomS3Lite）を用意する。両方ともキット番号・UIFlow2版・LED型番・LED数・最大輝度は未設定であり、講師がそれぞれ確認する。機種別の設定やBLE確認を自動で使い回さない。

構造例（番号も含め説明用。実物に合わせて講師が割り当て・確認すること）：

```typescript
export const workshopPresets: WorkshopPreset[] = [
  {
    id: 'kit-slot-a',
    profile: {
      ...sharedProfile,
      boardId: 'm5nanoc6',
      kitId: '001',
      features: { ...sharedProfile.features },
      baseline: { code: '', verification: null },
    },
  },
  {
    id: 'kit-slot-b',
    profile: {
      ...sharedProfile,
      boardId: 'atoms3lite',
      materialId: 'atom-s3-lite-led-workshop',
      displayName: 'AtomS3Lite LEDワークショップ',
      kitId: '002',
      features: { ...sharedProfile.features },
      baseline: { code: '', verification: null },
    },
  },
]
```

共通設定 `sharedProfile` に、講師が実機と教材で確認した値を記入する。

| 項目 | 記入・検証条件 |
| --- | --- |
| `boardId` | `m5nanoc6` または `atoms3lite`。機種と固定ピンを選ぶ。ブラウザ内では編集せず、キット選択で切り替える |
| `materialId` / `revision` | 教材識別子・Writerの設定版。UIFlow2の版とは別。安全な英数字等で設定 |
| `displayName` | 参加者が見分ける教材名 |
| `kitId` | 講師が割り当てた文字列。先頭の0を維持。英数字始まり、英数字・`_`・`-`、12文字以内 |
| `firmwareVersion` | 対象UIFlow2の正確な版。USBから取得したMicroPython版やfirmwareInfoで推測しない |
| `ledModel` / `ledCount` | 実際のLED型番と正の整数の個数。例示の37個などを自動採用しない |
| `ledBpp` | 本教材は3（RGB）のみ。4などを自動変換しない |
| `maxBrightnessPercent` | 講師が電源と実機を確認した上限。有限数・0超100以下。範囲に入るだけでは安全の証明にならない |
| `features` | `button`、`ble`、`controller` の利用希望 |
| `baseline` | 基準コード全文と、その内容・対象機種・対象版に結び付く講師の確認記録 |

未確定値は `null` にする。未設定や未解決の `{{...}}` を含む参加者用文面は出力させない。外付けLEDのGPIO2、機種ごとのボタンピン、bitstream encoding=0・800kHz用タイミング、GRB順、200msのフェード条件は設定画面で変更できる項目にしない。

### 機種別の配線

| 機種 | 外付けLED | ボタン（active LOW） | 内蔵RGB | その他の内蔵LEDピン |
| --- | --- | --- | --- | --- |
| M5NanoC6 | Grove G2 / GPIO2 | GPIO9 | GPIO20 | RGB電源 GPIO19、青色LED GPIO7 |
| AtomS3Lite | Grove G2 / GPIO2 | GPIO41 | GPIO35 | NanoC6のGPIO19・GPIO7制御は不要。流用しない |

定義の正本は [boards.ts](../src/config/boards.ts)。[M5NanoC6公式資料](https://docs.m5stack.com/en/core/M5NanoC6) と [AtomS3 Lite公式資料](https://docs.m5stack.com/en/core/AtomS3%20Lite) に照らして配線する。外付けLEDと内蔵LEDを同じものとして扱わない。SoCがESP32-S3というだけではAtomS3Liteと確定できない。

同じ配布設定内のキット番号は重複を避ける。ブラウザ内の検証は会場全体のID管理ではない。別のPCや配布ファイルの番号まで検出できたとは扱わない。

## ブラウザ内の講師用設定

参加者画面の「講師用設定」から不足項目を入力する。機種・教材ID・設定版は配布プリセット由来であり、更新時はリポジトリ側を変更する。対象機器とピンは講師用設定内に読み取り専用で表示する。機種を変えるときは「使うキット」で選び直す。講師の編集を適用しても、Writer内の編集中コード・機器情報・接続を変更しない。

未適用の変更または基準コードの読込み待ちがある間は、古い準備文のコピー・保存・プレビューを止める。読込み後に「設定を適用」してから利用する。既に実行したプログラムのエラー文脈は、その実行時の設定を保持する。

基準コードはテキスト欄または `.py` ファイルから登録できる。読み込みはデータとして行い、JavaScript/MicroPythonとして実行しない。コード本文は100000文字まで。長すぎるものは黙って切り詰めず、登録できないことを表示する。

講師がコードと対象機種・対象ファームウェアで実機確認した場合に限り、講師名などを添えて確認を登録する。新規登録は `verification.boardId` も記録する。アプリのテスト結果で実機確認済みとすることはない。コードまたは対象UIFlow2版を変更すると確認を失効させる。別機種の確認記録は有効にせず、キットの切替でも確認記録を移さない。

BLE基準コードがない、未確認、対象版が違う場合はBLEを利用不可にする。Webコントローラには追加でNanoLED v1対応の確認とRGB・1〜300LEDが必要。LED・ボタン用の設定が有効なら、その部分の相談用文面は生成できる。BLEは希望フラグと実際の利用可否を区別し、未準備のまま存在するように説明しない。

折りたたみUIは誤操作を減らすためであり、認証・アクセス制御ではない。原典と確認済み基準コードに矛盾がある場合、AIへ勝手な補正を依頼せず講師が解消する。未確認のBLE基盤はこの機能で新規開発しない。

## 保存・復元と教材更新

設定をブラウザへ保存する操作は明示的に行う。基準コードは通常メモリ上だけにあり、基準コードも保存する場合だけ講師が明示的に選ぶ。教材ID・設定版・プリセットID・対象機種が一致するデータだけを復元し、型・内容も再検証する。旧版データや壊れたデータを現在版へ黙って混ぜない。

機種識別子導入前の互換処理は、プリセットID `nano-c6-led-default`、教材ID `nano-c6-led-workshop`、設定版 `writer-ai-1` が一致し、`boardId` だけが存在しない旧設定に限り `m5nanoc6` を補う。機種不明の任意設定やAtomS3Liteへ移行しない。旧確認情報の機種省略もNanoC6でのみ有効とし、AtomS3Liteは機種を明示した実機確認を新たに登録する。言語設定 `mpw-language` は教材設定とは別に保持する。

保存機能が拒否された場合や容量超過の場合は、保存できなかった旨を表示する。現在のメモリ上の設定と通常の操作は続けられる。編集中のユーザーコード・シリアルログはAI準備の保存領域に入れない。Writerが以前から持つ編集コード等の保存とは別の領域で管理する。

教材・共通条件・プリセット構成を更新したら `revision` を更新する。新しい配布版の初期設定を確認し、必要なら新しい版に対して講師が再設定・再確認する。`writer-ai-1` は初期実装の設定版で、UIFlow2のバージョン番号や実機検証の認証ではない。

## コピー・ファイル保存で困ったとき

プレビュー、コピー、UTF-8 `.txt` 保存は同じ生成済み文面を使用する。コピー成功はクリップボードのPromise成功後にだけ表示する。拒否・未対応ならプレビューの読み取り専用欄を選択し手動コピーする。準備文には長さによる自動省略や分割を行わない。

10秒待ってもコピーが完了しない場合は、成功と表示せず手動コピーを案内する。ブラウザ側の書込み処理自体を取り消すAPIではないため、後からクリップボードへ反映される可能性はある。成功通知は [Clipboard.writeText の完了Promise](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText) に基づく。

基準コードを含む文面全体に秘密情報らしき代入が見つかった場合、コピーもファイル保存も確認してキャンセルできる。自動検出は補助であり、完全ではない。コードのコメント等に意図しない個人情報・秘密情報がないか、講師が確認する。

WriterはAPIキーを要求せず、自動でAIへ送信しない。利用者が各AIへ貼って送信した時点で、その内容は各サービスに渡る。保存してもAIの入力上限やコンテキスト消費が減るわけではない。特定の有料プランを必須とせず、無料・無制限とも保証しない。

## 原典と実行時テンプレートの対応

[prompt.md](../prompt.md) は教材原典として残す。実行時はMarkdownの見出しを切り出さず、以下の明示的な型付き設定とテンプレートを使用する。

| 原典・要件 | 実行時の担当 |
| --- | --- |
| Aのキット設定・講師確認情報 | `WorkshopProfile.ts` / `src/config/workshops.ts` |
| 機種・内蔵LED・ボタンの違い | `src/config/boards.ts` / プリセットの `boardId` |
| AのLED・ボタン・bitstream・GRB・最大輝度・200msの条件 | `WorkshopRules.ts` の共通ルール |
| AのBLEと0.3・[NanoLED v1仕様](ble-protocol.md) | 同じ共通ルール。利用できる場合だけ確認済みコード全文と必要仕様を含む |
| A末尾の返答とBの相談手順 | `StartPromptBuilder.ts`。準備完了の挨拶だけを要求せず、最初の質問1問を開始 |
| Hの静的チェックと実機確認の区別 | 初回文・共通ルール |
| エラー相談 | `RepairPromptBuilder.ts` が同じ共通ルールを使用。`useProgrammer` が操作・実行時の文脈を保持 |
| 保存データの復元・版照合 | `WorkshopStorage.ts` |
| コピー・ファイル保存 | `PromptExport.ts` / `AiPreparationPanel.tsx` |
| UIと生成文の言語 | `src/i18n/` / 各PromptBuilderの言語別テンプレート |

初回文にエラーテンプレート、E0、課題集、Writerの編集中コード・ログを無条件に混ぜない。教材の「UIFlow2コードモードへ貼る」は「UIFlow2ファームウェア上でWriterのRaw REPLから実行する」に置き換える。共有ルールは複数Builderへ長文を複製しない。

エラー修正では、エラー対象の操作・実行に対応するコードと教材設定を使用する。後で編集・キット変更しても古いエラーの依頼文を最新版へ差し替えない。実行コードを取得していない機器操作は未取得・対応未確認と明示し、エディタの内容を機器で実行済みと仮定しない。選択中の設定が不正なら不正と示し、通常用の汎用設定へ黙って置き換えない。

言語を変えると修正依頼の説明は再生成するが、エラー時のコード・ログ・機器情報・設定は同じスナップショットを使用する。実機の検出機種と選択教材が異なる場合は不一致を明示し、講師が機種と配線を確認するまでGPIO依存の修正版を確定させない。

## 確認範囲

`npm run lint`、`npm run test`、`npm run build` で検証する。型・値・プレースホルダ、BLE確認の失効、共有ルール、エラー文脈、コピー・保存とプライバシー、保存不可・破損・旧版、既存タブと接続の保持を個別に確認する。

自動テストやブラウザ内の模擬操作は、実機の発光・無線・USB動作や、外部AIの応答を保証しない。外部AIへの実貼り付け、USB/BLE実機、電源とLEDの安全性は別の受入確認であり、未実施なら `NOT RUN` と記録する。

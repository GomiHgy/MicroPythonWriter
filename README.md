# MicroPython Web Programmer

MicroPythonデバイスをUSB CDCシリアルで操作する静的Webアプリ。PC版 Chrome / Edgeでは **Web Serial API** を優先し、Androidでは **WebUSB CDC** が利用できればWeb Serial APIの有無によらず優先する。それ以外はWeb Serial、Web SerialがなければWebUSB CDC fallbackを使う。Android版ChromeからM5NanoC6を操作する経路も実装しているが、スマホ・OS・UIFlow2版の組み合わせでの接続・読み書きの実機受入は未完了。「プログラム」タブでコードを書込み、「コントローラ」タブでは **Web Bluetooth API** でLEDを操作・状態表示する。コードとシリアルログを外部サーバーへ送信しない。
想定機器は **M5NanoC6／AtomS3Lite**。機種ごとの内蔵LED・ボタンの違いを教材設定に反映する。対応表記は実機検証済みの保証ではなく、対象UIFlow2版と配線で別途確認する。

## 対応範囲

- **インストール・オフライン利用（PWA）**: ホーム画面・パソコンへ追加できる。初回オンライン準備後は、基本画面・コード編集・保存済みプログラムをオフラインで利用可能。大きいシミュレーターは希望したときだけ保存する。更新は明示操作とコード保存確認の後だけ行い、USB/BLE接続・シミュレーション中は拒否する。PWA化でブラウザの機器通信対応範囲は増えない。[追加・更新・オフラインの使い方](docs/pwa.md)

- **画面内シミュレーション**: 「プログラム」のエディタ右側で、編集中のコードのLED・本体ボタン・NanoLED BLE操作を試せる。狭い画面では縦並び。その下の「見守りログ」は折りたたみ式。USB接続は不要。ブラウザ内のCPython互換層で動かすため、UIFlow2/MicroPythonや実機を完全再現するものではない。対応する新しいChrome/Edge（WebAssembly JSPI必須）を使う。[使い方・対応範囲](docs/simulation.md)

ページ最下部に、アプリのバージョン（Gitコミットの先頭7桁）と生成日時（UTC）を表示する。機器のUIFlow2版とは別の情報。公開ビルドごとに自動で埋め込むため、利用時の外部通信は不要。未コミットの変更を含む場合はその旨を表示し、GitがないZIP環境などでは「取得できませんでした」とする。開発サーバーでは起動時点の情報になり、更新するにはサーバーを再起動する。

- USB書込み: PC版 Google Chrome / Microsoft Edge（Web Serial優先）、またはUSBホスト（OTG）対応AndroidスマホのChrome（WebUSB CDC優先、接続成功は実機未確認）。AndroidでWebUSBがなくWeb Serialだけが使える場合はWeb Serialを選ぶが、USB機器の列挙は端末対応次第。WebUSB側はEspressif VID `0x303a` のnative USB CDC-ACM構成が対象で、USB-UART変換器（CP210x / CH340等）は対応しない。両方のAPIが使えないブラウザではUSB操作を無効にする。[AndroidからのUSB操作・確認項目](docs/android-usb.md)
- Bluetooth: NanoLED v1/v2対応プログラムが必要。再生・停止・作品専用ボタンはv2対応時のみ。準備は下の「Bluetoothコントローラ」を参照。
- HTTPSまたは `localhost` が必要。GitHub PagesはHTTPSなので公開後そのまま使える。
- Web SerialのUSB VID/PIDは固定していない。WebUSB CDCはEspressif VID `0x303a` を絞り込んで選択し、CDC構成を検査する。どちらも「USBをつなぐ」を押してからブラウザ標準の選択画面を表示し、利用者の選択と許可が必要。許可キャンセルや接続失敗を理由に、別方式の選択画面へ自動移行しない。

### 表示言語

画面上部で **日本語／English／简体中文／繁體中文／Español／Deutsch／Français／한국어／Português** の9言語へ切り替えられる。操作ラベル・案内・確認ダイアログを翻訳し、言語はこのブラウザへ保存する（保存不可でもその画面では切替可能）。「AIの準備」・エラー修正・MicroPython版への書き直し依頼も、選択した言語でAIが質問・選択肢・回答・新規コードのコメントを返すよう指定する。追加6言語では長文の共通技術仕様を英語で同梱するが、回答言語を英語へ変更する指定は入れない。

コピーの隣に **「準備文をファイルで保存」／「修正依頼をファイルで保存」** がある。Androidなどで全文が貼り付けられない場合は、保存したUTF-8の `.txt` ファイルをAIの会話へ添付して送る。添付できないAIではファイルを開いて全文をコピーする。コード・設定・ログを省略せず保存するため、秘密情報を確認してから自分で送信する。保存通知はダウンロード開始の案内であり、端末への保存完了を保証するものではない。

言語変更でUSB/BLE接続、実行状態、編集中コード、未適用設定をリセットしない。ユーザーが入力したコード・基準コード・表示名・氏名、シリアルログや機器から取得した原文は翻訳しない。修正依頼は実行時のコード・機器・設定を保持したまま説明言語だけを切り替える。

## 安全設計

UIはシリアルポートへ直接触らず、`WebSerialTransport / WebUsbCdcTransport → RawReplClient → MicroPythonDevice / FileTransferService / BootModeService → hook → UI` の順で責務を分離している。方式の選択は `createSerialTransport` で行い、Raw REPL・ファイル転送・起動設定の処理は共用する。Raw REPLの制御バイトはプロトコル解析が終わるまで `Uint8Array` として保持する。

`プログラム更新`は、編集内容を`main.py.tmp`へBase64チャンク（既定384 bytes）で送信し、サイズ・SHA-256確認と `compile()` を通してから、既存ファイルを `main.py.bak` に退避してrenameする。転送中のUSB抜去・構文エラーでは既存 `main.py` の変更前に止まる。`/flash` は固定していない。更新だけでは実行せず、実行用コードも保持しない。`hashlib.sha256`が使えない環境では検査を省略せず停止する。

`通常動作`は推奨の操作状態で、実行中プログラムの停止確認、Ctrl-C、Raw REPL取得、古いWriter参照の解放を行い、NVSを変更しない。USB接続時に自動で準備する。復旧中の不要なUIFlow初期化を避けるため、接続・「USB操作をやり直す」ではsoft resetを行わない。`実行`は編集内容を`main.py`へ保存してから、ハードリセットではなくRaw REPLから実行する。

`実行`では作品全文を一時ファイルの確認時に1回だけコンパイルし、同じコードを単発実行する。保存後と起動直前は384バイトずつ読んでサイズ・SHA-256・準備トークンを確認し、古い準備や同サイズの改変も拒否する。REPLにソース全文を残さず、起動時の再コンパイルを避ける。[メモリ圧迫対策と実機受入手順](docs/execution-memory.md)を参照。メモリピーク低減の実装であり、実機のクラッシュ解消は別途確認が必要。

BLE初期化（対応するimport・`BLE()`・`active(True)`）をコードから検出できる場合、実行欄に **Bluetoothを先に準備する（起動時のメモリ対策）** を表示する。**初期状態はOFF**。利用者がONにして「実行」を押したときだけ、作品の停止と古いWriter参照の解放を確認し、新しいファイルの書き込み・作品全文のコンパイルより先に小さいコマンドでBLEを有効化する。既に有効なBLEはそのまま使い、コード・演出・Wi-Fi・GATT・NVS・自動起動設定は変更しない。失敗したら新しいプログラムを書き始めず停止し、panic・再起動後は明示的なUSB復旧または電源再投入・再接続を案内する。自動再試行やBLE解除は行わず、後続処理が失敗してもBLEだけONのまま残る場合がある。

Androidで共有された追加診断では、BLE有効化直前のPython空き222,480バイトに対し、ESP-IDF空き合計12,448バイト・最大連続領域10,240バイトが記録された。ネイティブメモリ圧迫を疑う観測であり、ファームウェア内部の原因確定や解消保証ではない。元コードを保管し、**電源再投入 → USB再接続 → 先行準備ONで「実行」1回** の順で `[MPW BLE PREP] BEFORE_ACTIVE / AFTER_ACTIVE` と診断版のBLE有効化前後を比較する。実機での対策効果は未確認で、電源投入時の自動起動には適用されない。[安全な比較手順](docs/execution-memory.md#同じ作品での安全な比較)を参照。

`main.py` が `while True` を含む常駐プログラムの場合、ファイル操作・プローブで使う有限コマンド用の完了待ちとは分離する。常駐プログラムはRaw REPLの受付後、`__M5_MAIN_STARTED__` を受信したら実行中として扱う。マーカーがない場合も2.5秒の起動猶予後に「実行中（起動マーカーなし）」とし、終了用の `0x04, 0x04, >` を10秒待ってエラーにはしない。実行後に終了シーケンスとstderrが届いた場合だけ、Tracebackを実行エラーとして表示する。

## 起動モード

- **動作OKとして自動起動**: `boot_option.set_boot_option(0)` を優先し、対応しない場合だけ検出済みの `esp32.NVS('uiflow').set_u8(...); commit()` を使う。実行後は確認のうえリセットする。
- **自動実行しない設定に戻す**: 同じ安全条件で `boot_option=1` を保存する。次回起動時に作品を自動実行しない。作品の `main.py` や編集中のコードは削除・上書きしない。
- `set_u8` がない環境で `set_i32` 等へ勝手に代替しない。安全に設定できない場合は書込み・実行だけを継続する。
- 保存後の読戻し値・成功マーカー・正常終了を確認してから、再起動を指示する。機器側例外や確認不一致を成功扱いせず、保存後に再起動手順が失敗した場合は「設定は保存済み」と「再起動手順は未完了」を分けて表示する。再接続時の取得値と実際の電源再投入で確認する。

### 自動起動した作品を、また編集するには

1. 本体のボタンを押さずに通常起動し、「プログラム」画面で機器をUSB接続して「USBをつなぐ」を押す。**通常、ダウンロードモードへの切替は不要。** 既に自動実行が始まっていても、Ctrl-Cで停止してUSB操作の確保を試みる。接続だけでは永続の起動設定を変更しない。
2. 実行欄の「自動実行を解除する・困ったとき」からガイドを開くか、下の「電源を入れた時の動き」を開き、**「自動実行しない設定に戻す」** を押して確認画面で続ける。Webアプリから実行中なら、停止完了後に設定を保存する。停止を手動で先に押す必要はない。
3. 保存結果を確認する。設定保存後に再起動を指示しUSB接続を閉じるので、USBをつなぎ直して **「自動実行 OFF」** を確認する。保存した作品は残り、「実行」でまた試せる。戻す案内は未接続でも「プログラム」画面に表示する。

停止と、自動起動の解除は別操作。「停止」や「USB操作をやり直す」だけでは、次回電源投入時の動作は変わらない。元に戻したい場合は同じ欄の「自動実行を再び使う」から明示的にONにする。接続・切断・設定変更の重複要求は受け付けず、古い機器の遅い完了通知で新しい接続を更新しない。

Ctrl-Cを無視するコード（割込み無効化・KeyboardInterruptの握りつぶし等）やネイティブハングはUSBだけで復旧できない場合がある。Raw REPLを取得できなければ、設定・ファイルを書き換えず失敗を表示する。ほかのUSB通信アプリを閉じて再接続し、解消しなければ機密情報を除いた見守りログを保存して調査する。自動的なフラッシュ消去・ファームウェア再書込みは行わない。

### 停止できない・フリーズする・再起動を繰り返すとき

「プログラム」→「電源を入れた時の動き」→ **「困ったとき：停止できない・フリーズ・再起動を繰り返す」** に、未接続時も開ける復旧ガイドを表示する。日本語・英語・中国語に対応。以下はアプリによる自動処理ではなく、利用者が行う手順。

1. M5Burner・UIFlow・ほかのシリアル通信アプリを閉じ、データ通信対応USBケーブル・別のUSBポートで試す。
2. 書き込み・設定変更中は電源を切らない。失敗表示後に電源を外してから外付けLED・周辺機器を外し、本体だけで再接続する。接続できるなら通常の解除手順を使う。再起動ループは電源不足や配線などでも起きるので、ファームウェアの再書き込みだけで直るとは限らない。
3. 復旧できなければ、編集欄のコードを手元のファイルへコピーし、必要ならブラウザの「プログラムを保存」も使う。これは機器内の最新版を読み出したバックアップとは限らない。ログを共有する場合はWi-Fi情報などの秘密情報を除く。**機器内にしかない大切なコードがある場合、消去・再書き込みの前に相談する。**
4. このアプリのUSB接続を切り、他のUSB通信アプリも閉じる。電源を外してLED・周辺機器を取り外し、対象機種の手順でダウンロードモードへ入る。

| 機種 | ダウンロードモードへの入り方 |
| --- | --- |
| M5NanoC6 | USBと外部電源を外す。正面の本体ボタン（GPIO9）を押したままUSBでPCへ接続し、電源が入ったら離す。[公式手順](https://docs.m5stack.com/en/core/NanoC6) |
| AtomS3Lite | USBでPCへ接続する。リセットボタンを約2秒長押しし、内部の緑LEDが点灯したら離す。離して緑LEDが消えるとダウンロードモード。作品用の正面ボタンとは異なる。液晶付きAtomS3などの別機種には流用しない。[公式手順](https://docs.m5stack.com/en/core/AtomS3-Lite) |

**ダウンロードモードに入るだけでは、自動実行はOFFにならない。** この状態ではUIFlow2が動作せず、本アプリからの設定変更・コード読み込みもできない。書き込みを行わずボタンを押さずに電源を入れ直すと通常起動へ戻るが、元の自動実行設定は残る。

復旧作業は、まず [NanoC6のUIFlow2公式手順](https://docs.m5stack.com/en/uiflow2/nanoc6/program)／[AtomS3LiteのUIFlow2公式手順](https://docs.m5stack.com/en/uiflow2/atoms3lite/program) を確認する。使用版のM5Burnerで `Configure` から起動設定だけ変更できる場合は、それを優先する。復旧できず再書き込みが必要な場合だけ、バックアップと消失リスクを確認したうえで、[NanoC6の書き込みページ](https://burner.m5stack.com/device/nanoc6)／[AtomS3Liteの書き込みページ](https://burner.m5stack.com/device/atoms3-lite) の対象機種の **UIFlow2.0** を手動で書き込む。**消去・再書き込みでは機器内のプログラムや設定が失われる可能性がある。** USBポートが変わる場合は接続先を選び直す。

`Boot Option` を選べる場合は `Show startup menu and network setup` を選び、`Run main.py directly` は選ばない。完了表示まではUSBを抜かない。完了後にM5BurnerのUSB接続を切り、ボタンを押さずに電源を入れ直して通常起動する。本アプリで再接続し **「自動実行 OFF」** を確認する。ONなら通常の解除ボタンを使用する。リンクを開くだけで接続・設定変更・消去・書き込みを始めることはない。

機種別手順は2026-09-30に公式資料と照合。実機での復旧確認は別途必要。

変更前のsoft resetが対象実機の不具合原因と断定はしていない。標準MicroPythonの[起動シーケンス](https://docs.micropython.org/en/v1.27.0/reference/reset_boot.html)ではRaw REPLのsoft reset時に通常`main.py`はスキップされるが、`boot.py`やUIFlow初期化は別途実行される。今回の対策は復旧経路から再初期化を除くもので、対象UIFlow2版での実機確認は別途必要。

実機受入では、自動起動ONで電源を入れて動作が始まった状態からUSB接続→OFF保存→再接続で値1を確認→電源を入れ直して作品が自動実行しないこと→既存コードの読込み／再実行を確認する。機種・UIFlow2版ごとに実施し、停止不能・USB抜去・設定書込エラーでは成功表示が出ないことも確認する。ホストテストは実機受入の代用ではない。

プログラム画面の主操作は「実行」と「電源を入れたら自動実行」の2つ。「実行」で編集内容を機器へ保存して動作確認し、その後「電源を入れたら自動実行」で確認画面を経て起動設定を保存・再起動する。自動実行ボタンは現在のコードと、この接続で書き込みを確認したコードが一致し、起動設定変更に対応する場合のみ有効。未反映の編集がある場合は先に「実行」を案内する。「実行」だけでは自動起動設定を変更しない。保存だけの「プログラム更新」と「保存済みのプログラムを読む」は、初期状態で閉じた「その他の操作」に移動している。

実行中にコードを直したら、そのまま「実行」を押せる。現在のプログラムを自動停止し、停止完了を確認してから編集内容を保存・実行する。「プログラム更新」も自動停止後に保存する（実行はしない）。停止失敗時には新しい書込みを開始しない。処理中の実行・更新の連打は受け付けず、USB切断後に古い処理が再開しないようにする。

「実行」の起動観察は、未処理例外を見つける補助でしかない。起動後に例外がなくても実機の動作成功とは断定しない。自動起動はユーザーが明示的に有効化する。

## 使い方

### 最初に使う画面

現在のタブは「AIの準備」「プログラム」「コントローラ」の3つ。初回は「AIの準備」を開き、以後は最後に選んだ表示可能なタブを復元する。「作品づくり」は操作を整理するため一時非表示にしているが、既存の作品データと実装は削除していない。以前のタブ選択が「作品づくり」だった場合も「AIの準備」を開く。タブ切替でコード・ログ・接続を破棄しない。

1. 「AIの準備」で機器・UIFlow2版・LED設定を確認し、準備文を好きなAIへ貼り付ける。
2. 得られたコードを「プログラム」に貼り付ける。手元にコードがあればAIを使わず直接貼り付けてもよい。
3. 名前と説明を付けてブラウザに保存し、USB接続後に「実行」で機器へ送って試す。ブラウザへの保存と機器への書き込みは別操作。
4. 無線対応プログラムなら「コントローラ」で接続し、実際の光と動きを確かめる。

### コピーしたコードをまとめて貼り付ける

「LEDやボタンの動きを書く場所」の「コード内のLED設定」では、コードからLED数と最大輝度を読み取り、数値入力と「コードに反映」で変更できる。トップレベルで一意に定義された `LED_COUNT` / `NUM_LEDS` と `MAX_BRIGHTNESS`（0〜1）/ `MAX_BRIGHTNESS_PERCENT`（0〜100）の数値代入に対応する。計算式・処理内定義・重複定義は変更せず理由を表示する。各項目は独立して変更でき、コメント・演出・GPIOは維持する。変更直後は「設定変更を元に戻す」も使える。コードの読込・貼り替え・手編集後は最新コードから入力値を読み直す。

これは編集中コードだけの変更であり、USB書き込み・実行・AIの準備設定・シミュレーターの表示個数は変更しない。機器では「実行」、シミュレーターではリセット後の再生で確認する。最大輝度を上げる場合は配線・電源と推定消費電流を確認する。

「LEDやボタンの動きを書く場所」の **「コピーしたテキストをペースト」** を押すと、その操作時だけクリップボードを読み、Pythonコードと判定できた場合に編集欄全体を置き換える。選択範囲への追記ではない。AIの回答が単一のPythonコード枠で囲まれている場合は、その枠を外してコードだけを貼り付ける。複数の候補・説明文だけ・空欄・大きすぎる内容などは置き換えず案内する。

成功時は通知し、貼り付け後にまだ編集していなければ「貼り付け前に戻す」で戻せる。読み取り待ちの間に編集・画面移動・通信処理が始まった場合は新しい内容を上書きしない。貼り付けによるUSB接続・実機への書き込み・実行は行わず、機器やLEDの設定も変更しない。エディターの従来のブラウザ自動保存は継続する。

クリップボード読み取りはブラウザの許可・対応状況に依存する。利用できない場合はコード欄を選び、Ctrl+A / Cmd+A → Ctrl+V / Cmd+Vで手動貼り付けできる。コード判定はブラウザ内のPython構文による補助で、安全性やMicroPython実機動作を保証するものではない。内容が分からないコードは実行しない。

### プログラムを名前付きで保存する

「プログラム」の「このプログラムを保存」を押し、名前・説明を入力し、機器・LED設定を確認して「名前を付けて保存する」を押す。保存リストには名前・説明・機種・LED型番・個数・外部GPIO・最大輝度・UIFlow2版・保存日時が表示される。UIFlow2版は任意。設定が不明なコードは機種を推測せず、手動で選択する。

- 保存するのは押した時点の編集コードと確認した設定。同名でも新しい項目として追加し、以前の保存を上書きしない。
- 設定は利用者が確認した注記で、コードからの自動抽出や実機確認の証明ではない。設定欄を変えてもコードや配線は変わらない。
- 「編集画面に読み込む」は確認後にコードと保存設定だけを復元する。現在の編集内容を先に退避し、「直前の読み込み・復元を取り消す」で戻せる。退避に失敗した場合は読み込まず、エラーを表示する。読み込んでもUSB/BLE接続・機器の停止・書き込み・実行は行わない。
- 「保存リストから削除」は確認した1件だけを削除する。編集中のコードや機器内のプログラムには触れない。
- 保存先はこの端末・このブラウザ・このサイト内のみ（`mpw-program-library-v1`）。他の端末やブラウザへの同期はなく、ブラウザデータの削除で失われる。大切なコードは手元にも保管する。
- 最大50件、保存JSON全体でUTF-8 2MB、1プログラム10万文字まで。名前は64文字、説明は1000文字まで。破損・未対応形式・容量不足の場合は元データを勝手に初期化せず、失敗を知らせる。

### 作品づくりの旧フロー（一時非表示）

以下は保持している作品づくり機能の仕様。現在の通常画面には入口を表示していない。

1. 機器・UIFlow2版・外付けLEDを選ぶ。
2. 電源を外して配線・DIN・共通GND・電源容量を確認する。
3. 入門プログラムを準備し、USB接続・実行・実際の点灯確認を分けて進める。
4. 名前・アイコン・色・速さ・繰り返し・終了状態を選び、光り方を組み立てる。プレビューは静的なイメージで、実際の点灯や動きの保証ではない。
5. 「短く1回押したら」「短く2回押したら」「長く押したら」と、押している間の操作、Bluetoothを選び、実機で確かめる。
6. 「動作OK版」を保存し、停止後に自動起動を設定する。設定書込み・リセットが成功した作品だけ、PCを外した動作確認へ進める。

**現在、提供側の実機確認済み入門プログラムは0件。** ボタン色切替・押下中点灯・NanoLED v2無線の候補コードと生成器を同梱している。設定が有効なら、実機未確認でも「試すコードを準備」で編集画面へ用意し、内容の確認・保存ができる。この操作だけではUSBへ書き込まず、接続・実行もしない。

機器で試すときは、利用者がUSB接続と実行をそれぞれ明示的に行う。未確認の入門プログラムは実行のたびに警告・確認を表示し、機種・UIFlow2版・外付けLEDのGPIO／個数／最大輝度・配線・電源を確認してから進む。実行は現在動いているプログラムを停止し、`main.py`を保存し直して起動するため、必要なコードは先に退避する。確認をキャンセルした場合は、その実行操作によるUSBへの書込み・停止・起動を行わない。不正な設定、検出した機種との不一致、処理中など実行できない状態は引き続き拒否する。

試行を許可しても「確認済み」にはならない。自動テストや利用者の「動作OK版」保存から提供側の検証済みへ昇格させず、[提供側の実機受入手順](docs/starter-validation.md)を完了してから対象の機種・版・設定・コード全文と一致する記録を公開する。「コードをファイルで確認する」を開き、「生成コードをダウンロード」で候補を保存することもできる。「AIの準備」でも同梱候補を実機未確認と明示して利用できるが、独自のBLE基準コードを確認済みとして登録する要件は変わらない。

### 作品づくりの本体ボタン設定（一時非表示）

「短く1回押したら」「短く2回押したら」「長く押したら」のそれぞれに、「次の光り方にする」「点灯・消灯を切り替える」「何もしない」を独立して設定できる。新しい作品の初期値は、1回＝次の光り方、2回＝何もしない、長押し＝点灯・消灯の切替。

候補コードは40msのチャタリング対策後に押下を判定する。1回目を離してから350ms未満に2回目を押すと2回押しの候補になり、2回目も短く離したときに2回押しだけを実行する。1回押しは区別のため350ms待ってから実行し、2回押しが「何もしない」でも1回押しを重ねて実行しない。800ms以上の長押しは1回だけ実行し、離したときに短押しを追加しない。時間内に始めた2回目を長押しした場合も長押しだけになる。「押している間だけ光る」を選んだ場合は、この3つの割り当てより優先し、長く保持しても点灯を続け、離すと消灯する。

旧作品の読込では、未設定の2回押しを「何もしない」として補い、旧長押しの「消灯する」は旧設定として保持する。既存コードや保存済みの動作OK版を自動で書き換えない。新しい割り当てを機器へ反映するには、作品を退避したうえでコードを明示的に準備し直し、実行・実機確認を行う。

### 作品づくりの一式保存と復元（一時非表示）

- コード・機器設定・光り方・リモコンの表示名／アイコンを一式で下書き自動保存する。「作品を保存」で名前付きの保存点を残し、`.mpw.json`へ書き出せる（1MB以内）。ブラウザに保持する作品は現在の1件。複数作品はファイルとして保管する。
- 「動作OK版」は現在実行したコード・設定との一致と、利用者による実機確認を要求する。実行開始表示だけでは記録しない。提供側のBLE確認証明とは別物。
- ファイル読み込みでは外部の動作OK記録を引き継がない。読み込み・動作OK版への復元の前には編集中の一式を退避し、「直前の読み込み・復元を取り消す」で戻せる。退避や一式保存ができない場合は置換を中止する。機器へは自動送信しない。
- 壊れた保存データや未知の形式を勝手に上書きしない。保存許可後も元データを別キーへ退避する。ブラウザの保存領域の削除には耐えられないので、大切な作品はファイルにも書き出す。
- 「AIで自分好みに広げる」は機器設定をAI準備へ渡す。実機確認情報を流用せず、未適用設定の置換は確認する。作品と食い違うAI準備情報はエラー修正依頼へ混ぜない。

### コードを直接使う場合

1. UIFlow2 / MicroPythonが動いている通常モードの機器をUSB接続し、このアプリをPC版Chrome / Edge、またはUSBホスト（OTG）対応AndroidスマホのChromeで開く。Androidの操作は[専用ガイド](docs/android-usb.md)を先に確認する（実機未確認）。
2. 「プログラム」タブの `USBをつなぐ` を押し、ブラウザのポート／機器選択ダイアログで対象を選ぶ（初期115200 bps）。
3. 接続時に自動で準備される通常動作で、検出された機器情報・カレントディレクトリ・ファイル一覧・boot_optionを確認する。
4. コードを編集し、保存だけなら`プログラム更新`、保存して起動するなら`実行`を使う。Ctrl+Sはプログラム更新、Ctrl+Enterは実行。
5. ターミナルの出力とTracebackを確認する。エラーでは該当行とAI修正依頼プロンプトを表示する。
6. 実際のハードウェア動作を確認してから、必要なら自動起動を有効にする。

「実行」「プログラム更新」の操作欄には、処理中と直近の結果を表示し、完了後も残す。「機器への書き込み」と「プログラムの実行」を分け、保存成功・実行開始待ち・失敗・USB切断を文章とアイコンで示す。保存だけの操作を実行成功とせず、実行開始後にエラーが届いた場合は結果をエラーへ更新する。結果が出た後にコードを編集すると、変更前の結果であり現在の編集内容は未反映と案内する。USB切断後の結果は切断前の情報であり、書き込み成功や実行開始の表示だけでは、実際のLED・ボタンの動作を保証しない。

画面は **USB接続 → コードとシミュレーション → 実行・結果 → プログラム保存 → 起動設定・復旧 → 見守りログ** の順。上部の3段階リンクで該当欄へ移動できる。未接続でも実行欄を無効状態で表示し、実行中の停止ボタンは接続欄に置く。失敗時はコード欄より前にも結果へのリンクを出す。保存・起動設定・ログは通常折りたたみ、起動設定の操作結果が届くとガイドを開く。並べ替えやガイドの開閉だけではコード送信や設定変更を行わない。

USBケーブルの抜線や再列挙を検出すると、操作は止まり「USB接続が切断された」画面へ切り替わる。再接続後は、許可済みポートを使う `許可済みポートへ再接続` を先に試す。OS側でポートが消えている場合は `USB接続を選び直す` を押し、ブラウザのポート選択を再度行う。切断中は書込み・実行操作を有効にしない。

AI修正依頼プロンプトはブラウザ内で生成され、API呼出しは一切しない。`password`、`passwd`、`pswd`、`api_key`、`token`、`secret`、`ssid` の代入らしき文字列を検出した場合は、コピー前に確認する。

プログラムのエラーでは、実行結果のカード内から「AIに修正を頼む文章をコピー」を使える。同じ場所の「コードを作ったAIとの会話へ送る → 修正版をコード欄に貼る → もう一度実行」の案内に従う。依頼にはエラー時のコード・設定・記録を使い、実行コードが未取得ならその事実を明記する。詳しいエラー記録は折りたたみ内に残し、コピーできない場合は依頼文を手動でコピーできる。USB切断は再接続を優先して案内する。

## AIの準備

「AIの準備」タブで使う機器を選び、UIFlow2ファームウェアの版とLEDの型番・配線を設定すると、その機器用の準備文を1つ生成する。キットIDや講師による設定は不要で、自宅でも使える。「AIに渡す準備文をコピー」→好きなAIの**新しい会話**へ貼り付けて送信→質問に答える→仕様確認後にできた `main.py` を「プログラム」へ貼り付けて「実行」、という流れで使う。これまでどおりAIの準備を経由せず直接プログラムを編集してもよい。

準備文・修正依頼文は、UIFlow2上のMicroPythonを維持し、完成した`main.py`全文を1つのPythonコードブロックで出す指定を冒頭とコード生成直前に置く。明らかなArduino/C++の`setup`・`loop`関数定義を検出した場合は、その場の「AIにMicroPython版を頼む文章をコピー」で同じAIとの会話へ戻せる。専用ペースト・通常の編集・保存/実行ショートカットからの誤書き込みを防ぎ、機器で動作中の作品は停止しない。判定はコメント・文字列内の例を除外する補助で、すべての言語違いやMicroPython非互換コードを検出するものではない。

UIFlow2ファームウェアをまだ書き込んでいない場合は、機器選択後の案内から [M5NanoC6用のM5Burner](https://burner.m5stack.com/device/nanoc6) または [AtomS3Lite用のM5Burner](https://burner.m5stack.com/device/atoms3-lite) を開く。選択した機器のページで **UIFlow2.0** を選んで手動で書き込み、完了したらM5BurnerのUSB接続を切って、このアプリへ戻り、実際に書き込んだ版を入力する。書込み済みならこの手順は不要。

ファームウェアの書込みで機器内のプログラムや設定が消える可能性があるため、必要なコードを先に保存する。WriterやほかのアプリがUSB接続中なら切断してからM5Burnerで接続する。リンクを開くだけではファームウェアを書き込まず、このアプリが版を自動取得・設定したり、コードをM5Burnerへ送信したりすることもない。

USB未接続・USB API非対応でも準備文は作れる。コピー、機器変更、タブ切替はUSB/BLEの接続・実行・編集中コードを変更しない。ChatGPT・Claude・Gemini・[DeepSeek](https://chat.deepseek.com/)・[Grok](https://grok.com/) のリンクは通常の外部リンクであり、文面を自動送信しない。ほかのAIへ同じ文面を貼って使うこともできる。AIごとのアカウントや利用条件は各サービスで確認する。

### 利用者の機器・LED設定

画面タイトルは「AIとフルカラーLED電飾をはじめよう」。機器の既定表示名は機種名のみとし、イベント参加やキット番号の割り当てを必要としない。

「AIの準備」の通常表示で、以下の5項目を利用者が入力・選択できる。有効な入力は機種別にブラウザへ自動保存する。適用ボタンや詳細設定を開く操作は不要。

| 項目 | 初期値・入力方法 |
| --- | --- |
| 対象UIFlow2ファームウェアの版 | 未入力。実際に使用する版を入力する。USBで取得したMicroPython版からは推測しない |
| LEDの型番 | 初期値はWS2812B。WS2812B / WS2812B-MINI / WS2812C-2020 / SK6812 / SK6812MINI から選ぶ |
| LED数 | 10個 |
| 最大輝度 | 20% |
| 外部LEDピン | GPIO2 |

保存先は現在のブラウザで、別ブラウザ・別端末には同期しない。不足・不正な設定のまま準備文を出力せず、保存できない場合は通知する。ファームウェア版と型番に推測の初期値は入れない。対象は **3チャンネルRGB（LED_BPP=3）** であり、SK6812系を選んでもRGBWへ自動対応・変換しない。型番の選択だけでは実機での適合を保証しない。

外部LEDピンは数値範囲内でも利用可能・安全とは限らないため、対象機器の出力可能GPIO、実配線、USB・内蔵LED・ボタンとの競合、電源条件を確認する。

機器・LED設定を変更しても既存のコードを書き換えたり実行したりしない。次に生成する準備・修正依頼に反映し、過去の実行エラーには実行時の設定を使う。対象版・LED条件の変更時は基準コードの古い実機確認を失効させる。基準コードやほかの詳細設定を自動保存するものではない。

実機確認の失効状態も保存する。設定を元に戻して再読み込みしても古い確認は復活せず、再確認したコードと確認情報を明示的に保存し直す必要がある。

### 詳細設定と配布用プリセット

配布用プリセットは [src/config/workshops.ts](src/config/workshops.ts)。M5NanoC6用とAtomS3Lite用を別々に用意している。共通の `sharedProfile` をもとに、固定のプリセット `id` と機種別の `profile` を定義する。`boardId`（`m5nanoc6`／`atoms3lite`）、内部の設定識別子・版・表示名、LED条件、使用機能を記入する。内部の `id` / `materialId` は保存互換性のためのキーであり、利用者に割り当てるキットIDではない。構造と更新・保存方法は [設定ガイド](docs/ai-preparation.md) を参照。

追加プリセットの構造例。`sharedProfile` の未設定値は、通常画面から実物に合わせて入力する。

```typescript
{ id: 'my-nano-c6-profile', profile: {
  ...sharedProfile,
  boardId: 'm5nanoc6',
  features: { ...sharedProfile.features },
  baseline: { code: '', verification: null },
} }
```

LED_BPP=3、選択機種のボタンピン、GRB、bitstream条件、OFF→点灯時200ms以上は固定仕様。設定が不足・不正なら準備文のコピーとテキスト保存は無効になるが、通常のUSB書込みは止めない。

基本欄の **「どう操作する？」** で本体ボタン・Webリモコンを選べる（両方も可）。準備文へ即反映し、操作方法だけを機種別に自動保存する。WebリモコンONはBluetoothもON、OFFはBluetoothもOFF。既存の独自Bluetooth設定は別の案内で識別する。基本欄の変更はコード・基準コード・未適用の詳細設定を勝手に保存・実行しない。

「詳細設定」では表示名・独自のBluetooth通信・BLE基準コードなどを補完できる。機種とピンは読み取り専用で表示し、機種変更は通常画面の機器選択で行う。折りたたみは認証・権限制御ではない。**Webコントローラを試すだけなら、基準コードの登録は不要。** 有効な登録コードがなければ、機器・LED設定に合わせた同梱NanoLED v2候補を準備文へ全文収録し、実機未確認と明示する。設定不備や候補の対応範囲外では、設定の確認を案内する。独自Bluetooth通信だけを利用する場合は従来どおり対象機種・UIFlow2版の実機確認済み基準コードが必要で、ない場合もLED・ボタンの相談は続けられる。

有効な登録済みコードは同梱候補より優先する。v1だけの確認をv2へ昇格せず、再生・停止・アクションを利用可能と案内しない。古い確認や現在設定と一致しない登録コードがある場合も、登録内容は書き換えず、準備文には別の同梱候補を使用することを明示する。NanoC6の確認をAtomS3Liteへ流用せず、試用やアプリの自動テストから確認情報を作成しない。

詳細設定の未適用変更・基準コードの読込み中は、古い準備文を取り違えないようコピーとファイル保存を止める。読込みが終わり、必要項目を確認して「設定を適用」すると再び使える。通常画面の5項目には適用操作は不要。

使用機能でWebコントローラをONにすると、Bluetoothも自動でONになり、OFFにはできなくなる。WebコントローラをOFFにするとBluetoothの固定を解除するが、自動ではOFFにせず、利用者が切り替えられる。旧保存設定でWebコントローラだけがONの場合も復元時に補正する。機能の選択は実機確認の代わりにはならない。

Webコントローラが利用可能な準備文では、AIが本体ボタンだけでなく「本体ボタン／Webリモコン／両方／おまかせ」から操作方法を確認する。本体ボタンがOFFならボタンと両方を候補に出さない。無線では状態確認・明るさ・消灯・モード切替、v2では再生／停止・一度だけのアクションも相談する。質問は選択機能と通信仕様に合わせ、1回1問・最大6問の範囲で行う。

物理ボタンを使う場合はシングルクリックを基本に、「ダブルクリック・1秒長押しも使うか」を質問する。「シングルだけ／ダブルも使う／1秒長押しも使う／3種類すべて／おまかせ」から選び、使用する押し方の動作を確認する。ボタン無効・Webリモコンのみ・回答済みの場合には重ねて質問しない。新規コードは標準で長押し1000ms・ダブル待ち350ms・約40msのチャタリング対策とし、非ブロッキングでシングル・ダブル・長押しの重複発火を防ぐ。既存作品・登録基準の明示された時間や動作は無断変更しない。

シミュレーターの内蔵ボタン欄も「シングルクリック」「ダブルクリック」「1秒長押し」の3ボタンになっている。各ボタンを1回選ぶと仮想GPIOの押下・解放を再現し、作品の判定処理を試す。操作中は次の入力を待ち、一時停止・リセット・画面切替で入力を解除する。対応する判定処理がないコードに機能を自動追加するものではない。時間条件は[シミュレーション仕様](docs/simulation.md)を参照。

### コピー・保存・プライバシー

プレビュー・コピー・UTF-8テキスト保存は同じ生成文を使う。コピーが拒否・非対応の場合は「準備文の内容を見る」の読み取り専用欄を選択して手動コピーする。成功通知はコピー完了後だけ表示し、AIへの送信や設定完了とは表示しない。コピー・ファイル保存の両方で、持ち出す全文に秘密情報らしき代入があれば確認できる（検出は補助で、完全ではない）。

基準コードは原則メモリ上だけで保持し、ブラウザへの保存は明示操作でのみ行う。保存内容は内部の設定識別子・版・プリセットID・対象機種に紐づけ、復元時も検証する。設定版を変えた際に旧設定を自動移行しない。旧データの `kitId` は捨て、それ以外の有効な設定は維持する。旧形式の型番が5つの選択肢に一致しなければ、勝手に読み替えず選び直しを案内する。既知の初期NanoC6プリセットで機種IDだけがない旧保存データはNanoC6として復元するが、AtomS3Liteへは移行しない。破損・容量超過・保存不可では警告し、新機能がアプリを落とさないようにする。編集中コードやログをこの設定領域へ保存しない。

WriterはAI API・独自チャット・解析機能を追加せず、自動で外部送信しない。ただし、自分でAIへ貼り付けて送った内容は、そのAIサービスへ送信される。AIに渡す固定仕様はコードを強制するサンドボックスでも実機確認の代わりでもない。

エラーの修正依頼も初回準備文と同じ固定仕様を使う。実行時のコード・機器情報・設定を保持し、その後の編集や機器変更と混ぜない。実行コードを取得していない機器操作は未取得と明示する。AI準備を使わない通常利用では汎用修正依頼を維持し、選択中の設定が不正な場合はその問題を明示する。

## Bluetoothコントローラ

LEDの状態、明るさ、再生・停止、作品ごとのモード・アクションを1画面で操作する。v2機器が返すカタログから名前付きボタンを表示し、速度は対応する作品だけ表示する。旧v1機器は従来の4モードとスライダーを維持する。USB接続とBluetooth接続は別々で、タブ切替だけでは接続や実行中プログラムを終了しない。

v2接続後は「作品のボタン名とアイコンを変える」で表示名を作品へ保存できる。機器が報告したIDだけを使い、通信コマンド・プログラムは変更しない。未対応IDの保存名からボタンを作らない。「作品を使う画面にする」で大きな操作表示へ切り替え、切断時には準備案内へ戻る。任意RGB色の無線送信は追加していない。

未接続でも再生・停止・モード・アクションの操作欄を無効状態で表示する。主表示は **未接続／接続中／状態待ち／受信中／更新停止** で、通信状態とv1/v2の仕様を分ける。仕様は「操作のしくみ・通信仕様」に折りたたみ、未受信なら未確認とする。更新停止・切断中に表示が残る場合は、再生状態・LEDの色・設定値を最後に受信した情報として明示する。スライダーの選択値は機器の報告値と分離して保持する。更新停止や受信待ちが続いたら、その場の再受信ボタンを使える。接続中は状態が古くても消灯を送れるが、送信成功は実行完了の保証ではない。準備案内は「どう操作する？」でWebリモコンON → 同梱試用またはAI → 対応コードを実行 → Bluetooth接続に統一し、作品の消灯・演出終了の動作を一律に断定しない。

### 最初の準備

**NanoLED v1またはv2対応のBLEプログラムを先に実行する必要がある。** 再生・停止・アクションはv2が必要。従来の「文字を受信するだけ」のBLEプログラムは自動互換ではなく、接続ボタンがプログラムを自動で書き込むことはない。

本リポジトリには対象UIFlow2で実機確認済みのBLE基準コードは含まれていないが、**実機未確認のNanoLED v2試用プログラム**を同梱している。通常利用で基準コードの登録、UUIDや通信コマンドの入力は不要。最初に試す場合は「AIの準備」で機器・LED設定を入力し、基本欄の「どう操作する？」でWebリモコンをONにする。適用ボタンは不要。表示される案内から次の順に進む。

1. **対応プログラムを準備**：ブラウザ内の作品コード・機器設定・操作ボタンを試用用に置き換える。コードが空の場合も置換を確認し、現在の作品を一時退避する。退避・保存ができなければ中止する。この操作ではUSB接続・書込み・実行を行わず、基準コードの確認情報も変更しない。「作品づくり」の「直前の読み込み・復元を取り消す」で退避した作品へ戻せる。
2. **機器で実行する**：USB接続後に「実行」を押す。同梱候補が未確認の場合は毎回、機器・UIFlow2版・配線・電源・LED設定と書込みの影響を確認する。起動時は消灯している。
3. **リモコンで試す**：USB側の「停止」は押さず、「Webリモコンを開く」でコントローラへ進む。Bluetoothで接続し、機器から状態が届いてから明るさ・再生／停止・モード・アクションを試し、実際のLEDも確認する。

有効な登録済みコードを使う場合は、そのコードを維持してAIへ相談し、下記の接続手順へ進む。独自の基準コードを作成・更新する開発者は [prompt.md の0.3節・プロンプトE0](prompt.md) と [通信仕様](docs/ble-protocol.md) に従い、実機確認後に確認情報を明示登録する。v1確認からの自動移行はしない。同梱候補を試せることと、確認済みとして利用・配布できることは別である。

1. PCの「プログラム」タブで対応コードを「実行」する。
2. 「停止」を押さず、「コントローラ」タブへ切り替える。
3. 「Bluetoothでつなぐ」を押し、自分のプログラムに設定された `NanoLED-` で始まる機器名を選ぶ。同名がある場合は、自分の機器の電源で出現・消失を確認して見分ける。
4. 状態が届いたら、明るさ、再生・停止、表示された作品のモード・アクションを使う。v1ではピンク・ブルー・マジック・にじいろ・消灯とスライダーを使う。

「停止」は今の色を保ってアニメーションを止め、「消灯」はLEDを黒にする。モードは継続する光り方、アクションは一度だけ実行する演出。演出中の再押下は作品ごとの明示指定を優先する。指定がなければ、同じアクションでもう一度押すと今の光から再スタートし、別のアクションなら切り替わる。「アクション実行中の追加ACTIONは無視する」と指定した作品では、機器側コードが追加要求を捨て、開始時刻や完了予定を変えず現在の演出を続ける。AIの準備文・修正依頼もこの優先順位を伝え、意図的な無視処理を勝手に再スタートへ変更させない。同梱SPARKLE候補は指定なしの既定動作を使い、最後の実出力から200msでつなぎ、最後の受付から約1秒で完了して、最初の演出前のモード・位相・再生状態へ戻る。どちらの場合も連打をあとでまとめて実行することはない。途中でモード変更・停止・消灯でき、未接続・状態未受信・更新停止・送信中の制限は維持する。

Webは演出中も押下ごとにACTIONを1回送るが、再スタート・無視を強制せず、機器の作品プログラムに任せる。旧v2でも意図的な無視を指定した現行作品でも、追加ACTIONを無視する場合がある。既存コードはWeb更新やBLE再接続だけでは変わらない。動作を変えるには作品仕様に沿うコードを準備し直し、USBから明示的に書込み・実行して実機確認する。保存済み作品・登録済み基準コードを自動で置換しない。「送信済み」は実行完了の証明ではなく、現在のアクションは機器からの状態報告で確認する。同じアクションIDが届くだけでは、個々の再押下を受け付けた証明にはならない。作品名は機器が送る平文で、画面言語を変えても翻訳しない。詳しくは[アクションの再スタート・切替](docs/ble-protocol.md#アクションの再スタート切替)を参照。

リモコンの「ライトを消す」は `OFF` を1回送り、対応プログラムが現在の出力色から **200ms（0.2秒）でフェードアウト**する。明るさスライダーの設定値は保持し、機器のメインループで処理するためBLE通信や本体ボタンの受付を止めない。起動時・例外時などの安全な即時消灯とは別の処理。以前に生成・保存・書込みしたコードは自動更新されないため、既存作品を保存したうえで、新しい候補コードを準備し直すかAIで既存コードの `OFF` 処理を更新し、機器で「実行」して確認する。電源再投入後も使う場合は更新後のコードを保存し、自動起動での動作も確認する。旧コードへの接続だけではフェード対応にならない。

安全のため、「消灯」だけはBluetooth接続後、状態がまだ届いていなくても送れる。ただし、送信できたという表示だけでは実際の消灯を保証しない。

明るさ100%は、準備画面で設定した安全上限の100%。上限そのものを引き上げない。明るさ0%では現在の光り方を残して暗くし、「消灯」中にスライダーを動かしても点灯しない。速さ0%は停止ではなく最もゆっくり。

明るさ・スピードのスライダーには「設定したい値」を表示し、操作後はその値を保持する。機器の状態通知が遅れたり、本体ボタン・モード変更で別の値になっても、つまみを勝手に戻さない。実際に受信した設定値はスライダー下の「機器から受信」に別表示し、送信だけで反映済みとは判断しない。状態の更新が止まった場合は「最後に受信」として通常操作を無効にするが、選択値は保持し、受信復帰だけで再送はしない。接続し直した場合は新しい接続先の受信値から始め、以前の値を自動送信しない。

画面のLEDは、機器が最後に送信したRGB出力の報告を表示する。本体ボタンで変えた状態も通知で反映される。送信した操作だけで表示を成功扱いにせず、未受信・古い状態を区別する。発光をセンサーで測る機能ではないため、実際の配線や光り方は目で確認する。Bluetoothを切っただけでは消灯を保証しないので、消したいときは先に「消灯」を押す。

### 対応環境と困ったとき

NanoLED v2の作品専用ボタンは、モードとアクションの**合計16個まで**。共通の再生・停止・消灯・状態取得やスライダーは別枠。同梱の無線候補にはSPARKLEが1個あるため、モードは最大15個。AIとの相談でも希望を数え、超える場合は勝手に削らず整理案を確認する。[準備文の件数確認](docs/ai-preparation.md#webリモコンをまず試す)を参照。

新しい候補の状態通知は、接続直後は20バイトずつ送り、実際にMTU交換を確認できた接続だけ最大244バイトへ拡大する。交換できなくても20バイトで継続する。旧20バイト送信プログラムは引き続き使えるが、更新前のWeb側は9個以上のモードに対応しない。**Web更新だけでは機器内のmain.pyは変わらない**ので、作品を保存したうえで対応コードを準備し、明示的に書き込み・実行 → コントローラで接続 → 受信状態と実物のLEDを確認する。既存作品・登録済み基準コード・実機確認記録は自動更新しない。[通信仕様](docs/ble-protocol.md#分割と頻度)と[実機未確認の受入項目](docs/starter-validation.md#mtu可変notifyと16操作の受入)も参照。

Windows/macOSのChromeまたは対応するデスクトップEdge、AndroidのChromeで利用する。iPhone/iPadの標準ブラウザ、Safari、Firefoxの標準機能は対象外。HTTPSまたは `localhost`、OSのBluetooth有効化とブラウザへの許可が必要。アプリは実際のAPI対応も確認する。詳細は [Chromeの公式ガイド](https://developer.chrome.com/docs/capabilities/bluetooth) と [Web Bluetoothの実装状況](https://github.com/WebBluetoothCG/web-bluetooth/blob/main/implementation-status.md) を参照。

Web Bluetooth非対応またはHTTPS条件を満たさない環境では、初期表示から「Bluetoothでつなぐ」を無効にし、ボタンのあるカード内に理由と対応ブラウザを表示する。機器選択のキャンセルや接続許可の拒否はブラウザ非対応とは区別する。

- 機器が見つからない：対応プログラムが実行中か確認する。ほかのスマートフォンやアプリが接続していれば、そちらを切断する。
- 接続できるが状態が届かない：対応プログラムを実行したか確認し、必要ならUSBで再実行してBluetoothをつなぎ直す。古いUUID・通知なし・異なるJSON形式は自動変換しない。
- USBで再実行したら切れた：USBの接続準備・実行・停止・更新・リセットでBLEプログラムが停止することがある。対応プログラムを再実行してBluetoothをつなぎ直す。
- 切断された：機器の電源とプログラムを確認し、接続ボタンから選び直す。以前のLED表示を現在の状態だと判断しない。

## 復旧と既知の制約

USBシリアルへ接続できない場合、NanoC6の **GPIO9ボタンを押したままUSBケーブルを接続** するとESP32-C6のFirmware書込み用Download Modeへ入れる。この操作は通常の `main.py` 書込みとは別。必要に応じてMicroPythonファームウェアを書き直す。本アプリはMVPとしてファームウェア書込み機能を含まない。

上記はNanoC6専用の復旧操作であり、AtomS3LiteのGPIO41ボタンへ読み替えない。AtomS3Liteの復旧は [機種別の公式手順](https://docs.m5stack.com/en/core/AtomS3%20Lite) を確認する。

- Python例外が出ない論理的な不具合は自動判定できない。
- Web Serial / WebUSBの両方が非対応のブラウザではUSB書込みを利用できない。WebUSB経路は対象CDC構成に限り、OSドライバや他アプリの占有によって接続できない場合もある。BluetoothはWeb Bluetooth APIの対応が別途必要。
- firmwareによって `boot_option` モジュールが存在しない可能性がある。
- ユーザーコードがUSB CDCまたはREPLを無効化すると接続できなくなる。
- ハードウェア依存処理、USB再列挙、UIFlow固有APIは実機確認が必要。
- 実機がない状態のテストはFake Serial / Fake MicroPythonによるもの。
